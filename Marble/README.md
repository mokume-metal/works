# Marble — 墨を流して混ぜる水盤

![生成りの紙の上に、墨・藍・臙脂・黄土の輪が十数本重なっている](https://i.gyazo.com/14ce2706b5367f4285970f34f8636fb9.png)

制作トラック ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md)) の 13 本目。

**絵は毎フレーム解いた流れの積分結果である。** 置いている図形は全画面の矩形 1 枚だけで、
水面の速度も 4 つの顔料の濃度も GPU の並び (`Numbers`) にある。1 フレームにつき計算
(`compute`) を 32 回頼み、非圧縮 Navier–Stokes を 1 歩進めて顔料を運ぶ。**works で計算を
使う 1 本目**で、既存 12 本は 1 本も使っていない。

**混ぜても濁らないところを見てほしい。** 非圧縮の流れ (`∇·v = 0`) は場所を作りも消しも
しないので、顔料は**伸ばされて畳まれるだけ**で薄まらない。パレットで絵の具を練れば灰色に
なるのに、墨流しが何度かき混ぜても色を保つ理由がこれである。

![梳く・滴を落とす・混ざるの 6.5 秒](https://i.gyazo.com/337132fccabe4a2e4b1a4f53faf19b69.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` と同じ観測の区画へ要求を置いて
> 書き出した絵で、画面は撮っていない)。幅 720・15fps・98 枚で 6.5 秒。**3 つの操作を
> 順に通してある** — ① 左下から右上へ梳く (輪が折れて渦が 2 つ立つ) ② 同じところへ
> 滴を 3 回落とす (臙脂 → 藤黄 → 墨。**後の滴が前の滴を外へ押し出して輪になる**)
> ③ 右から左へ梳く (落とした輪が伸びて他の筋へ巻き込まれる)。

![梳いた後。渦の腕に沿って 4 色が別々の筋のまま並んでいる](https://i.gyazo.com/ccd22091624cfae94af9033b07dcc4c1.png)

## 走らせる

```bash
mokume run Marble -c release    # 作って走らせる
mokume watch Marble             # 保存したら作り直して差し替える
mokume mcp Marble               # 走っているスケッチを外から観測する
```

**`-c release` でなくてもよい。** debug でも 60fps を保つ — 毎フレームの仕事がほぼ全部
GPU にあり、CPU は手の跡を数個詰めるだけだからである (下記「速さ」)。

**いまは `mokume run` が通らない。** 道具の側ではなく Swift 6.4 の既定のビルドシステムの
問題で、works のどの作品も同じところで落ちる (下記「踏んだもの」)。抜け道は
`swift build --build-system native` で作って実行ファイルを直に叩くこと:

```bash
swift build --package-path Marble -c release --build-system native
MOKUME_WORK_DIR="$PWD" ./Marble/.build/release/Marble
```

## 触る

| 操作 | 効くもの |
| --- | --- |
| マウスを動かす | **かき混ぜる。** 動いた向きと速さがそのまま水を押す |
| ドラッグ | 同じ。1.7 倍の強さで梳く |
| クリック | いまの顔料の滴を落とす。**周りを押しのける**ので、同じところへ続けて落とすと同心円になる |
| 1 … 4 | 顔料を選ぶ (墨・藍・臙脂・藤黄) |
| C | 落とすたびに色を回すかどうかを切り替える (既定は回す) |
| Space | 水を止める。**絵は残る** |
| R | 起動時の同心円へ戻す |

**Space で止めた水は、触るまで動き出さない。** 息 (下記) も一緒に止めてある — 止めた
はずの水がまた動き出すと、止まったことを確かめられないからである。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。** この作品の
コミットを checkout すれば mokume も当時の版に戻る。**works で `v0.8.1` を引く 1 本目**で、
既存 12 本は 0.7 系である ([#49](https://github.com/mokume-metal/works/issues/49) が追随を追う)。

`0.7.1` → `0.8.1` で通らなくなった口は `ObservationReport` の 2 つだけで、この作品は
触れていない。

**同じ絵は二度出ない。** 流れは前のフレームの場から積分するので、`time` も `frameCount`
も読んでいないのに、同じ操作をしても同じ絵にはならない (浮動小数の丸めと、手の跡が
届くフレームの違いが効く)。**指紋を持たせていない**ので、版を上げて何かが動いたことに
気付くのは窓を開けて目で見たときである。

### v0.9.0 で動いたもの — 差が時間とともに育つ

**`v0.8.1` → `v0.9.0` で、1 枚目はほぼ同じなのに、3 秒後には別の絵になっている。**

| フレーム | 動いた画素 | 差の平均 | 最大の差 |
| --- | ---: | ---: | ---: |
| 1 | 93.5% | 0.60 | **4** |
| 61 | 96.8% | 10.45 | 234 |
| 121 | 99.1% | 24.18 | 230 |
| 181 | 99.3% | 28.59 | 233 |

**これは描き方が変わったのではなく、流れが分岐したのである。** 1 枚目の差は最大 4 / 255
— 色の作業空間が変わったぶんの、墨を落とした直後の 1 階調でしかない。ところがこの
作品の絵は**毎フレーム解いた非圧縮 Navier–Stokes の積分結果**なので、その 1 階調が
次のフレームの初期値になり、伸ばして畳むたびに開いていく。

**走らせるたびの揺らぎも同じ形で育つ** (同じ `v0.9.0` で 2 回撮った床は 0.04% → 15.68%)
が、版上げの差はその 2 倍ほど速く育つ。**初期値に鋭敏な作品では、版差を「絵の違い」と
して測れるのは最初の数フレームだけ**である — ここで言えるのは「1 枚目は最大 4 しか
違わない」までで、その先は分岐の記録にしかならない。

**上の絵は貼り替えていない** — もともと同じ絵が二度出ない作品なので、貼り替えても
「版で動いた」ことの証跡にはならない。

## 何がどう動いているか

### 格子は 2 段にしてある

| 場 | 格子 | 1 マス | 本数 |
| --- | --- | --- | --- |
| 速度 | 320 × 180 | 画面の 6 × 6 画素 | 2 (`u`, `v`) |
| 圧力・発散・渦度 | 320 × 180 | 同上 | 1 |
| 顔料 | 1920 × 1080 | **画面の 1 画素** | 4 (顔料ごとの濃度) |

**圧力を解くのは粗くてよいが、顔料は細かくないと筋が潰れる。** 圧力は場の全体へ効く
滑らかな量なので、Jacobi を 24 回回すのに細かい格子は要らない。一方で墨流しの見どころは
髪の毛ほどの筋なので、顔料には画素と同じ細かさを与えてある — **36 倍のマス数**で、
渦の芯が灰色に潰れる範囲が目に見えて狭まる。

`Numbers` は 11 本 (速度 ×2・圧力 ×2・発散・渦度・顔料 ×3・手の跡・滴)、合わせて 124 MB。

### 1 フレームは 32 回の計算である

| 段 | 計算 | 回数 | 何をするか |
| --- | --- | ---: | --- |
| 1 | `carry` | 1 | 速度が速度を運ぶ (semi-Lagrangian) |
| 2 | `spin` → `swirl` | 2 | 渦度を測り、渦度確信・息・手の跡を足す |
| 3 | `spread` → `press` → `settle` | 26 | 発散を測り、圧力を 24 回解いて、勾配を引く |
| 4 | `carryInk` → `carryBack` → `carryFix` | 3 | 顔料を MacCormack で運ぶ |
| 5 | `soak` | 0 か 1 | 落とした滴を置く |

**待ち合わせは 1 行も書いていない。** `compute` へ渡す `reads` / `writes` が束ねる先で
あると同時に依存の宣言でもあるので、順序は宣言から導かれる。

### 顔料は MacCormack で運ぶ

素の semi-Lagrangian (1 回汲むだけ) は**数値拡散**でみるみる灰色になる。運んだ先をもう
一度**時間を逆に回して**戻し (`carryBack`)、元の場と重ならない差を誤差とみて半分だけ
先回りして引く (`carryFix`) と、同じ格子のままで筋が数分保つ。

補正は汲んだ 4 マスの上下限で抑えてある。**箍が無いと筋の縁に負の濃度が出て、白い縁取り
として見える。**

### 色は足し算ではなく掛け算で混ざる

顔料が持っているのは色ではなく**吸収係数**である。濃度 `c` の顔料を通った光は
Lambert–Beer で `exp(-σc)` になるので、重なった顔料は**指数が足し算・透過率が掛け算**に
なる。

| | 吸うもの (線形 RGB) | 濃度 1 での見え方 |
| --- | --- | --- |
| 墨 | 2.85 / 2.90 / 2.60 | 青をわずかに残した黒 (青墨) |
| 藍 | 3.60 / 2.60 / 1.00 | 紺 |
| 臙脂 | 0.90 / 3.20 / 2.70 | 深い紅 |
| 藤黄 | 0.55 / 1.45 / 3.10 | 黄土 |

藍と臙脂が重なれば紫に沈み、4 つが重なれば黒へ寄る。**どれだけ重ねても白へ飛ばない** —
`mix` でも加算でもこうはならない。

### 滴は水を押しのける

落ちた滴は水面に場所を作り、そのぶん周りの膜を外へ押し出す。だから**同じところへ続けて
落とすと同心円になる** — 輪を描いているのではなく、前の滴が押し出されて輪になっている。
墨流しの輪はもともとそうやってできる。

押しのけは `r → √(r² + R²)` の逆写像で作ってある。**この写像は面積を保つ**
(`d(r'²)/d(r²) = 1`) ので、膜は伸び縮みせずに外へずれるだけになる。

**速度へ外向きの力を足す形ではできない** (最初はそう書いて、何も起きなかった)。放射状の
速度は発散そのもので、次の段の非圧縮の射影が丸ごと消してしまう。滴が押しのけるのは
**2 次元の膜の中の場所**であって、水の湧き出しではない。

### 息 — 触らなくても、水は完全には止まっていない

大きな渦をひとつ、流れ関数 `ψ` の回転として足してある。**回転として足すので発散が出ず**、
圧力の段が消す成分を持たない。強さは手で押す力の 20 分の 1 ほどで、数十秒かけて模様が
ゆっくり歪む。

### 紙と、水に浮いていること

地は生成りの楮紙で、縦横に細長い揺らぎを 2 方向重ねて繊維にしてある。顔料の厚みの傾きから
2 つを出す:

- **縁の濃まり** — 厚みが急に変わるところを少し濃くする。溜まったところが濃く見えるのと同じ
- **水面の照り** — 傾きを法線にした弱い鏡面。**顔料のあるところだけ光る**ので、
  「紙に写した後」ではなく「まだ水に浮いている」ことが読める

## 速さ (2026-09-16 の実測)

Apple M3 Max / macOS 26.6.2 / mokume `v0.8.1` / 1920 × 1080 / 顔料 2,073,600 マス。

| 構成 | fps | 1 フレーム平均 | 最大 | 記憶 |
| --- | --- | --- | --- | --- |
| release | 60.0 | 16.67 ms | 16.69 ms | 659 MB |
| debug | 60.0 | 16.67 ms | 16.69 ms | 633 MB |

**debug と release で差が出ない。** 毎フレームの仕事はほぼ全部 GPU にあり、CPU がやるのは
手の跡を 16 個まで詰めて `Numbers` へ書くことだけだからである — 1 フレームの仕事の大半が
CPU にあった [Prism](../Prism/) (3.2 倍の差) とはちょうど裏返しになっている。

滴を落としたフレームだけ計算が 1 つ増え、`R` で置き直したフレームは 25 ms かかる
(同心円を 207 万マスぶん書き直すため)。どちらも 1 フレームだけである。

## 直したこと

### 筋に沿って山形のギザギザが出た

圧力を**中央差分の発散**と**5 点の Laplacian**で解いていた。この組み合わせは、偶数マスと
奇数マスが互いに相手を見ない — 発散と勾配は 2 マス幅の飛び石なのに、圧力だけ 1 マス幅で
解かれるからである。分かれた 2 枚の格子はそれぞれ勝手な圧力を持てるので、市松模様の圧力が
消えずに残り、**絵には筋に沿った山形の皺**として出た。

発散を前向き・勾配を後ろ向きに取ると、合成した作用素がちょうど 5 点の Laplacian に一致する
(速度を半マスずらして置いたのと同じことになる)。これで皺は完全に消えた。

### 一振りで模様が水盤の外まで飛んだ

手の速さを水へ写す倍率が 21 で、渦度確信が 2.4、抵抗が 0.22 だった。**一度撫でただけで
模様が画面の端まで流れ、渦の芯が灰色に潰れた。** 倍率 7・確信 0.9・抵抗 0.5 にして、
速さの上限 (110 マス毎秒) も置いた。渦度確信は下げると細い渦が早く潰れるが、上げると
格子の目のサイズの渦を自分で作り出す。

### 渦の芯が広く灰色に潰れた

顔料の格子が 960 × 540 (画面の 2 × 2 画素) だった。画素と同じ 1920 × 1080 へ上げると、
潰れる範囲が目に見えて狭まった。**60fps は変わらない** — 増えたのは GPU の仕事だけで、
まだ頭打ちに届いていない。

### 顔料が印刷インキのようだった

最初の係数は原色に寄っていて、4 色が並ぶと CMYK の試し刷りに見えた。藍を紺へ、臙脂を
深い紅へ、藤黄を黄土へ寄せた。**輪の太さと濃さも輪ごとに変えて**あり、位相を半径で
ゆっくり回してあるので隣の輪とは違う形に歪む (揃えると全部が相似形になり、手で落とした
ものに見えない)。

### 止めたはずの水が、また動き出した

`Space` は速度を 0 にするだけだったので、息がすぐ吹き直して模様が動き続けた。**止めたら
触るまで息も吹かない**ようにした。

### 線が濡れたゴムのように見えた

水面の照りを 0.34、法線の傾きを 2.6 にしていたら、墨の筋が盛り上がった艶のある紐に
見えた。照りを 0.15、傾きを 1.5 まで落とし、代わりに縁の濃まりを 0.32 → 0.42 へ上げた。

## 踏んだもの

### `swift build` も `mokume run` も通らない (works 全体)

Swift 6.4 の既定のビルドシステム (`swiftbuild`) は、mokume が
`resources: [.process("Drawing/Shaders")]` で運んでいる `.metal` を**資源ではなく原文として
組み立てようとする**。同梱の断片は前置き (`Common.metal` など) と連結して初めて意味を持つ
ので、単体では `use of undeclared identifier 'floor'` の類で落ちる。

**この作品に限らない** — Pond でも同じところで落ちる。`--build-system native` を渡せば
通るが、`mokume run` / `watch` の内側には渡す口が無いので、**道具から走らせられない**。
この作品は `swift build --build-system native` で作った実行ファイルを直に叩いて作った。

戻した先: [mokume#1268](https://github.com/mokume-metal/mokume/issues/1268)。**起票は既に
あった** (前日に道具の側が同じところで踏んでいた) ので、**作品の側から見た影響**
— 道具の内側に `--build-system native` を渡す口が無く、works はどの作品も走らせられない —
をコメントで足した。直し方 (`.copy` にする) は既にトリアージで決まっている。

### 走らせ直すと、前に送った入力がもう一度配送される

[Pond が踏んだもの](../Pond/README.md) と同じ ([mokume#1143](https://github.com/mokume-metal/mokume/issues/1143))。
`.mokume/input/request.json` が残っていると、起動のたびに応答済みの要求が再生される。

**この作品では、窓口から送った「右へ梳く」動きが起動のたびに再生され、誰も触っていないのに
中心から右へ噴流が立った。** 手を入れていないのに絵が動くので、**渦度確信か息の暴走を
疑って 2 回も作り直した** — つまみを 0 にしても症状が消えないことで、ようやく入力のほうへ
辿り着いた。既知の不具合だが、**症状が「スケッチのバグに見える」ため、知っていても
引っかかる**。
