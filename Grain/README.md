# Grain — 挽いた板を並べた面

制作トラックの最初の 1 本 ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md))。板 6 枚を別々の種から作り、年輪・節・繊維を手続き的に置く。

![挽いた板を並べた面 (frame 312)](https://i.gyazo.com/8cf96b6561e41b05a9164cc98b54f93f.png)

## 走らせる

開発は CLI から。この作品は 1 つの SwiftPM パッケージで、`mokume` の単位そのものになっている。

```bash
mokume run .      # 作って走らせる
mokume watch .    # 保存したら作り直して差し替える
mokume mcp .      # 走っているスケッチを外から観測する
```

書き出しは実行ファイルへ直に渡す (CLI は引数を通さないため)。

```bash
swift run Grain slab                       # 板を立体にして回す (未完成 — 下記)
swift run Grain --render <置き場> <番号>     # 1 枚だけ書き出す
swift run Grain --frames <置き場> <数> slab  # 連番で書き出す
```

### 版を上げたときに動いたもの — `v0.1.0` 相当 → `v0.5.0`

依存は当初 `main` を指していた — 立体と光 (2026-08-28) を含まない `v0.1.0` しか無かったためである。`v0.5.0` がそれを含むので追随をやめ、Garden と同じくタグで固定した (`a919d8f` → `v0.5.0`、その間 124 コミット)。

**平面の絵は 10 画素だけ動いた。** 1280x720 のうち、動いたのは**すべて右端の最終列** (x=1279) で、y は継ぎ目 (120 刻み) の ±1 に限られる。継ぎ目は `line(0, y, width, y)` で引いており、動いたのはその**終端画素のアンチエイリアス**だけである。

| y | 左隣 (x=1278) | 右端 旧 | 右端 新 |
| --- | --- | --- | --- |
| 119 | (27,9,2) | (5,1,0) | (31,12,2) |
| 601 | (40,21,6) | (9,2,1) | (42,22,7) |

**旧版は右端で線が濃くなりすぎていた** — 左隣より暗い。新版は左隣と揃う。線の中心 (y=120 など) は 1 ビットも動いていない。上の絵は貼り替えていない (10 画素は目で見て分からない)。

**立体 (`slab`) の絵は完全に一致する。** 動いたのは平面の線の終端だけだと言える (上の `slab` のハッシュはその後の書き直しで別の値になっているが、この版上げでは 1 ビットも動いていない)。

### 版を上げたときに動いたもの — `v0.5.0` → `v0.6.0`

**平面の絵はほぼ全面が動き、立体 (`slab`) はまた 1 ビットも動かなかった** (上の `slab` のハッシュが `a0a1d3e1…` から動いているのは、この版上げではなく[下記の書き直し](#止まっていたところ--v060-で動いた)による)。1280x720 のうち差のある画素は 290048 (31.5%)、うち 3 以上が 14.3%・10 以上が 7.8%。全体の明るさは +0.19%。

**動きの大きさは面の下ほど大きい。**

| y の帯 | 平均の差 | 差 10 以上 |
| --- | ---: | ---: |
| 0-59 | 0.95 | 0.3% |
| 180-239 | 1.23 | 5.3% |
| 420-479 | 2.92 | 12.3% |
| 660-719 | 3.12 | 11.3% |

**これは `drawDaylight()` の形そのものである** — 上を明るく下を 0.66 倍まで落とす帯を `blendMode(.multiply)` で 64 段重ねており、掛け算の効きが強いところほど差が出ている。四隅がさらに動くのは (14)、その上に枠を 44 重ねているためである。

**正体は塗りの縁の被覆で、3 行のスケッチで切り分けられる。** `rect(4, 4, 16, 8)` (整数の境界に載る) は両版で 1 ビットも変わらず、`rect(4, 20.5, 16, 8)` (半端な境界に載る) だけが変わる — 旧版は半分掛かった行を落とし (0)、新版は被覆どおりに置く (188)。64 段の帯は `t * height` の**半端な位置**に載るので全段がこれに当たり、掛け算で積み上がって面の下ほど差が開く。

改善の方向なので mokume へは戻していない。**上の絵は貼り替えた** — 貼ってあったのは `383ca101…`、つまり `v0.5.0` へ上げる前 (`a919d8f`) の絵だった。前回は「10 画素は目で見て分からない」として据え置いたが、そのぶん**2 版ぶん古いまま**になっていた。

## 作り

- **年輪** — 板の下にある芯からの距離を歪ませて縞にする。晩材は輪の 1 割ほどの細い濃い帯
- **節** — 距離場を持ち上げて輪を巻き込ませ、芯を濃く、そのすぐ外を明るい輪にする
- **繊維とむら** — 長手に緩く・幅方向に細かい揺らぎを 2 段で重ねる

木目は 1 度だけ焼いて `Image` に持ち、継ぎ目と光は描画の側で置く。

### 作りながら直したこと

- **年輪の弧が出ず、水平な縞になっていた。** 芯を板の下 `d` に置くとき、長手方向の係数 `s` が `d` と同じ桁に無いと山形にならない (持ち上がりは `d - sqrt(d² - (s/2)²)`)
- **節のまわりが細かい網に割れていた。** 輪を強く引き寄せすぎて 1 画素に複数の輪が入っていた
- **艶の帯が白く飛んでいた。** 足し込みは飽和する

## 止まっていたところ — `v0.6.0` で動いた

[`Slab.swift`](Sources/Grain/Slab.swift) は長らく**未完成のまま残してあった**。板を立体にして回すと、輪郭は変わるのに木目が画面に貼り付いたまま動かない。

![板は回るのに木目が動かない (書き直し前)](https://i.gyazo.com/d487ccc553c11889b8258b24e8c87119.webp)

**塞いだのは `Fragment.shapePosition` である。** 置き場所の変換を通す**前**の座標なので、形を動かしても回しても変わらない。板の長手 (x) と幅 (z) をこれで取り、板の座標 0…1 へ直して木目の式へ渡している。厚みの側 (y) は使わない — 挽いた板の面はこの 2 軸で決まり、木口はその断面として現れる。

![木目が板に留まって回る](https://i.gyazo.com/15707b4cf79588cdc1874c07736972b0.webp)

> 撮影範囲: 書き出した連番 PNG (`--frames out-slab 60 slab`) から作ったもので、画面は撮っていない。60 フレーム (5 秒・12fps)、板は 41 度回っている。**木目が板と一緒に流れる**ところを見てほしい。

**留まったことは画素でも測れる。** 板の内側に画面固定の窓 (80x40) を置き、frame 0 と比べる:

| | frame 0 → 5 | → 15 | → 30 | → 59 |
| --- | ---: | ---: | ---: | ---: |
| 書き直し前 (`in.place`) | 0.00 | 0.00 | 0.00 | 0.00 |
| 書き直し後 (`shapePosition`) | 16.72 | 18.43 | 18.70 | 19.47 |

**書き直し前は 59 フレーム進んでも 1 も動かない** — 板の輪郭だけが動き、模様は画面に貼り付いていた。書き直し後は窓の中身が入れ替わる = 模様が板と一緒に流れている。

`shapePosition` は**寸法そのままの値**を返す (`box(520, 26, 300)` なら x は −260…260) ので、0…1 へ直すのに寸法が要る。板の寸法を 1 か所に持ち、断片へも同じ数を渡している。

## mokume へ戻したもの

**3 本とも閉じた。消さずに残す** — 何を踏んで、どれが何で塞がったかは記録である。

| 踏んだもの | | いま |
| --- | --- | --- |
| シードから同じ値が出る乱数とノイズが無い | [mokume#366](https://github.com/mokume-metal/mokume/issues/366) | 閉じた |
| 断片が立体の表面の位置も向きも受け取れない | [mokume#367](https://github.com/mokume-metal/mokume/issues/367) | 閉じた (`Fragment.shapePosition` / `shapeNormal`)。**`Slab` を塞いだのはこれ** |
| 焼いた画像を立体の面に貼る口が無い | [mokume#368](https://github.com/mokume-metal/mokume/issues/368) | 閉じた (`texture(_ image:)`)。`Slab` では使っていない — 断片で作るほうが解像度に縛られないため |

経過は [works#1](https://github.com/mokume-metal/works/issues/1)、記録が古いままだったことは [works#7](https://github.com/mokume-metal/works/issues/7)。

**戻さなかったもの**も 1 つ — 断片で塗った立体が平坦に見えたが、`mokume_fragmentMain` は光を当ててから `in.color` へ入れて `paint` を呼んでいた。こちらの書き方の誤りで、mokume の欠けではない。
