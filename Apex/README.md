# Apex — 3 周を走って順位を競う

![主ストレート。前を行く白い車を、赤い車が追っている](https://i.gyazo.com/ea2b033f1cdc36586a8b2050d230b3c2.png)

制作トラック ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md)) の 14 本目。

**works で勝ち負けのある 1 本目。** 13 本の作品はどれも終わらない眺めで、触れる
[Prism](../Prism/) (場面を動かす)・[Quarry](../Quarry/) (世界を掘る)・[Marble](../Marble/)
(水をかき混ぜる) にも、目的や終わりは無かった。ここには始まりと終わりがあり、**相手がいる**。

| 初めて | いままで |
| --- | --- |
| **勝ち負けと終わりがある** (順位・ラップタイム・ゴール) | 13 本すべてが「終わらない眺め」 |
| **自分以外に動くものが意思を持つ** (AI の対戦車 3 台) | 動くものは全部、時刻か物理の関数だった |
| **対象を追いかけるカメラ** | 固定・軌道 ([Helmet](../Helmet/))・一人称 (Quarry) はあったが、追うカメラは無い |
| **視野角を速さで動かす** | 13 本すべて `perspective` の視野角は定数 |

**原理を説明する計器は出していない。** 素直に遊べるものとして作ってあり、出るのは
速さ・周回・時計・順位だけである。

## 走らせる

```bash
swift build --package-path Apex -c release --build-system native
MOKUME_WORK_DIR="$PWD" ./Apex/.build/release/Apex
```

問題で、works のどの作品も同じところで落ちる (下記「踏んだもの」)。上の抜け道で走る。

## 触る

| 操作 | 効くもの |
| --- | --- |
| `W` / `↑` | 踏む |
| `S` / `↓` | 止める。止まってから踏み続けると下がる |
| `A` `D` / `←` `→` | 曲がる |
| `Space` | 引き手。**横のタイヤを諦める**ので尻が出る |
| `R` | 並べ直す |

**操作の手引きは画面に出していない。** 出すと 13 秒ほどで GPU が 1 フレームも描けなく
なるためで、理由は下記「踏んだもの」にある。**この表がその代わり**である。

合図 (3 → 2 → 1) の前は踏んでも進まない。**待っている間は物理そのものを止めてある** —
進めると、グリッドが坂にかかっているだけで転がり出す。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。**
[Marble](../Marble/) と同じ `v0.8.1` である。

**同じ操作からは同じ走りが出る。** 物理はフレームの長さではなく **1/120 秒の固定刻み**で
進めるので、機械の速さでラップタイムが変わらない。相手の走りも同じ刻みの上にあり、
乱数は使っていない (揺らぎは時刻から引いた雑音なので、同じ時刻には同じ値になる)。

## 何がどう動いているか

### コース — 制御点 15 点から 1.2 km

主ストレート 158 m → 高速右 → 中速右 → バックストレート → **ヘアピン** → S 字 →
最終左。これを**向心 Catmull-Rom** (α = 0.5) で閉じ、弧長で 2 m 刻みに再サンプルする。

**一様版 (α = 0) を採らない。** ヘアピンの前後で制御点の間隔が急に詰まるので、一様版だと
接線が過大になって**路面が自分と交差する**。向心版はループも尖りも出ないことが分かっている。

**縮尺合わせに反復は要らない。** 向心の節点は点の間隔の**比**しか使わないので、制御点を
k 倍すると節点はすべて √k 倍になって比が変わらず、**曲線は厳密に k 倍の相似形・弧長も
厳密に k 倍**になる。生の長さを 1 度測って割るだけで狙いの 1 周に合う — **実測 1200.0006 m**
(狙いは 1,200 m)。

**刻みは 20 単位に固定せず `全長 / 個数` で割り切る。** 固定にすると最後の 1 区間だけ
長さが違い、周回の継ぎ目で曲率が跳ねる。

位置からコース上の (距離・横ずれ) を引くのは**前のフレームの添字の ±8 だけ**を見る。
1 フレームに進むのは最大 8.7 単位で、サンプルの間隔 20 単位より短い — **1 サンプルも
進まない**ので、この窓は過剰に安全である。

### 「全開では曲がれない」は 1 行から出る

```text
命じる角速度 = v·tan(δ) / ホイールベース     ← 自転車モデル
出せる角速度 = grip / v                     ← タイヤが出せる横 G の上限
実際         = clamp(命じる, ±出せる)
```

**コーナーごとの上限速度を手で書いたところは 1 つも無い。** 上の 3 行から、

| | 半径 | 回れる速さ |
| --- | ---: | ---: |
| ヘアピン | 17 m | **54 km/h** |
| 高速コーナー | 86 m | **120 km/h** |
| 全開のまま (480 単位/s) | **177 m** が最小 | — |

が出る。**全開ではヘアピンの半径の 10 倍の円しか描けない**ので、踏んだままでは物理的に
曲がれない。

**滑りは車体を回した「後」に生まれる。** 向きを変えても速度はその瞬間には変わらないので、
新しい車体の軸で測り直すと横向きの成分が残る。タイヤはそれを 1 歩あたり `grip·h` だけ
削るので、普段は 0.1 秒ほどで消える。限界では削る速さより生まれる速さが勝ち、**一定の
角度で滑り続ける**。

足の下は中心線からの横ずれだけで決まる。草の最高速は釣り合いを解いて **36 km/h** —
「落ちたら終わり、でも戻ってこられる」の線である。

### 相手は人と同じ操作しか返せない

AI が返すのは `Controls` 構造体 (踏む・止める・曲がる・引き手) だけで、**物理は誰が
運転しているかを知らない**。「AI だけが余分に曲がれる」ことが構造的に起きないので、
相手が速いとしたらそれは同じ車をうまく操っているからである。

速さを決めるのは**制動距離を織り込んだ後ろ向きの走査**である。

```text
目標速度 = min over Δ ( √( v_corner(κ(s+Δ))² + 2·a·Δ ) )
```

先の曲率から「そこを回れる速さ」を出し、**そこまでに詰められるぶんを足して**今の上限に
する。これが無いと、コーナーの入口で急に止まるか、突っ込んで飛び出すかのどちらかになる。

**ライン取りは手で引いていない。** 広い窓 (±60 m) で均した曲率を横ずれに写すだけで、
**平均の遅れがそのままアウト・イン・アウトになる**。

**ラバーバンド (順位で相手の性能を上下させる) は採らなかった。** 見えないところで
不公平をやると、勝っても負けても納得が残らない。代わりに**全員へ等しく効くスリップ
ストリーム**を置いてある — 前の車の 20 m 以内では空気抵抗の 2 乗の項が 45% 減るので、
長い直線で後ろの車が伸びる。**人が使っても同じだけ効く。**

3 台の腕前は 0.96 / 0.91 / 0.86 と散らしてあり、「1 台には勝てる、1 台とは競る、
1 台は速い」の並びになる。

### 追うカメラは特別扱いを 1 つも持たない

注視点を**コースの先**に置くだけで、コーナーでは視線が内側へ回り込む。「コーナーだったら
内を向く」という場合分けは書いていない。

カメラが居るのは「車の向き」と「進んでいる向き」の**間** (0.55) である。車の真後ろだと
滑るたびに世界が振り回されて酔い、経路の真後ろだと車が画面を横切って滑る。0.55 は
**車の横腹が見えるが、進む先も見えている**中間である。

硬さは時定数で決める。`mix(いま, 狙い, 0.1)` と書くと**速い機械ほどカメラが硬くなる**ので、
`1 − exp(−dt/τ)` の形で追う。

**視野角は 62° から 74° まで速さで広がる。** 速度計を見なくても速さが分かる、いちばん
効く仕掛けである。

### 路面に絵を貼らない

舗装に絵を繰り返し貼ると、**寝た面なので遠くで必ず滲んで踊る** (mokume の `Image` は
縮小の段を持たない)。ここは頂点の色だけで組み、速度感は**縁石の縞** (2 m 周期)・
リングごとの陰の揺らぎ・木立・視野角の広がりで出している。

**縁石の縞はコーナーだけに出す。** 直線の両脇までずっと縞だと、どこが曲がっているのかが
遠目に読めない。曲率が半径 167 m より小さいところは白線になる。

**スタートラインは別の板を重ねない。** リング 0 の路面そのものを市松に割るので、
同一平面の重なりが 1 枚も生まれず、z が競って散ることが原理的に起きない。

## 速さ

**観測 (`mokume mcp`) が返した数字。**

| | |
| --- | --- |
| コースを組んで焼く | **12.6 ms** |
| 走っている間 | **60.0 fps** (平均 16.67 ms / 最悪 18.7 ms) |
| 記憶 | 326 MB |
| 路面の頂点 | 32,538 (600 リング × 9 帯) |
| 木 | 109 本を**描画 1 回**で置く |

**3 周のレースは 148.7 秒で終わり、ベストラップは 38.33 秒**だった (1.2 km を平均
113 km/h)。周を重ねるとラップが 42.17 → 40.73 → 38.33 と詰まる — ライン取りが曲率の
移動平均から出ているので、**速さが乗るほど先読みが伸びて線が寝る**ためである。

## 踏んだもの

### この機械では `mokume run` / `watch` がどの作品でも通らない

[mokume#1268](https://github.com/mokume-metal/mokume/issues/1268)。Xcode 27 (Swift 6.4) の
既定のビルドシステムが mokume の `.metal` を単独でコンパイルして落ちる。**Apex だけで
なく Quarry でも同じところで落ちる**ので、作品側の問題ではない。既知だったので新しくは
起票していない。抜け道は上の「走らせる」のとおり。

### 使う字の種類が増えると、その時点から GPU が 1 フレームも描けなくなる

[mokume#1273](https://github.com/mokume-metal/mokume/issues/1273) に戻した。**手元の表示を
日本語で書いたら、1 フレームも描けなくなった。**

切り分けに 12 回作り直した。効いているのは文字数でも、文字の大きさでも、`text()` を
呼ぶ回数でもなく、**スケッチが使う字の種類**だった。

| 手引きの 2 行に出した文字列 | 新しい字 | |
| --- | --- | --- |
| `"W go S stop"` / `"AD turn R zero"` | W g o S s t p D u r n z e | **13.5 秒で止まる** |
| `"LAP 1 / 3"` を 2 行 (ほかの行と同じ字) | **なし** | 走り続ける |

**止まる地点はコースの同じ場所 (s ≈ 415 m) で、毎回そろっていた。** そのせいで最初は
コースの幾何か、そこで描かれる木か影を疑った — 焼いた頂点を全部数えて壊れた値が
1 つも無いことを確かめ、影も後処理も木も車も地面も 1 つずつ外し、**最後に残ったのが
文字だった**。

日本語が 1 文字で落ちたのも、`textSize` を毎フレーム変えると落ちたのも (**同じ字でも
大きさが違えば別のグリフ**)、長い行で落ちたのも、全部これで説明が付く。

**警告の文面は「描きすぎ」と言う。** 実際には路面 32,538 頂点・木 109 本・車 4 台・影を
全部描いたままでも、字さえ増やさなければ 60fps で走り続ける。逆に**それらを全部消して
文字だけ出しても止まる**。

いま出している字は**数字・`:`・`.`・`/`・`-`・空白・`LAP`・`BEST`・`P`・`km/h`** だけで、
**新しい字を出す場面をすべて畳んだ** — 操作の手引きは README へ移し、合図の `GO` は数字に、
着順の `FINISH` は外した。**着順は 1 度しか出ない場面なので、そこで初めて使う字があると
取り返しがつかない。**

### `createShape` の中では `push` / `translate` / `rotate` が効かない

組み込みの立体 (`box` / `cylinder`) を変換して焼こうとすると**全部が原点に積み上がる**。
車輪が縦のまま車体に刺さった絵が出て気付いた。車体も路面と同じように頂点を自分で
並べる形にした。

### 壁の罰を速度そのものに掛けると、壁から出られなくなる

1 歩 (1/120 秒) あたり 0.985 倍は 1 秒で 8 割方削るので、擦っている間ずっと止まって
いた。いまは**壁へ向かう成分だけを消し**、罰は 0.997 に落としてある。

### 踏まなかったもの — `Placement` の変換順

`Placement` の変換は **T·Rx·Ry·Rz·S** の順に積まれるので、点にはロール → ヨー → ピッチの
順で効く。**ヨーが 90° の車にピッチを与えると、車体はロールする** — コースの向きに
よって車が横に傾くという、見つけにくい壊れ方をする。先に読んで気付いたので、車は
`push / rotateY / rotateX / rotateZ / pop` で置き、`Placement` は**色を掛けるためだけ**に
使っている。ヨーしか使わない木立には `shape(_:at:)` をそのまま使える。
