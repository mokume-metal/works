## 走らせる

```bash
swift build --package-path Apex -c release --build-system native
MOKUME_WORK_DIR="$PWD" ./Apex/.build/release/Apex
```

**`mokume run Apex` は通らない。** 道具の側ではなく Swift 6.4 の既定のビルドシステムの
問題で、works のどの作品も同じところで落ちる (下記「踏んだもの」)。上の抜け道で走る。

車の運動とレースの進みにはテストがある (**works で初めてテストを持つ作品**)。絵を
書き出す口でも組み立てを測る口でもなく、物理が約束している振る舞いの検査である。

## 触る

| 操作 | 効くもの |
| --- | --- |
| `W` / `↑` | 踏む |
| `S` / `↓` | 止める。止まってから踏み続けると下がる |
| `A` `D` / `←` `→` | 曲がる |
| `Space` | 引き手。**横のタイヤを諦める**ので尻が出る |
| `R` | 並べ直す |

**操作の手引きは画面に出していない。** 出すと 13 秒ほどで GPU が 1 フレームも描けなく
なるためで、理由は下記「踏んだもの」にある。**この表がその代わり**である。

**合図は灯で出す。** 画面の上に丸が 3 つ並び、1 秒ごとに赤く灯って、**全部が緑に
変わった瞬間から走れる**。緑になる前は踏んでも進まない — **待っている間は物理そのものを
止めてある**ので、グリッドが坂にかかっていても転がり出さない。緑になる前から `W` を
押しておけば、その瞬間に走り出す。

**逆走すると、画面の中央に進むべき向きを指す赤い矢印が点滅し**、右上の地図の自分の印が
赤く点滅する。コースに沿って後ろへ 14 km/h より速く進み、それが 0.8 秒続いたときに
出る (壁から下がって抜け出すだけなら出ない)。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。**
いまは `v0.9.0` である。

**同じ操作からは同じ走りが出る。** 物理はフレームの長さではなく **1/120 秒の固定刻み**で
進めるので、機械の速さでラップタイムが変わらない。相手の走りも同じ刻みの上にあり、
乱数は使っていない (揺らぎは時刻から引いた雑音なので、同じ時刻には同じ値になる)。

### v0.9.0 で動いたもの

**`v0.8.1` → `v0.9.0` で、ほぼ全画素が動いた。** 1280x720 のうち 92.9〜93.0% (4 枚とも)、
差の平均は 2.4 / 255。**赤の面がいちばん大きく** (4.0)、緑は 1.1 にとどまる。

**走らせるたびの揺らぎは 0.12% / 0.010 しか無い**ので (同じ `v0.9.0` で 2 回撮って測った)、
この差はまるごと版差である。

**正体は色の作業空間である。** 数で書いた色が sRGB の原色として解かれるようになった
ぶんで、空・路面・車体の彩度が手本の色見本どおりに落ち着いた。形も縁も動いていない
(切り分けは [Garden](../Garden/README.md#v090-で動いたもの) が背景 1 画素で示している)。
このときは絵を貼り替えなかった (並べても区別が付かない)。**いまの絵は
[#88](https://github.com/mokume-metal/works/issues/88) で運動と画面を直したあとに
`v0.9.0` で撮り直したもの**である。

## 何がどう動いているか

### コース — 制御点 18 点から 1.2 km

主ストレート → 高速右 → 中速右 → バックストレート → **ヘアピン** → S 字 → 最終右。
これを**向心 Catmull-Rom** (α = 0.5) で閉じ、弧長で 2 m 刻みに再サンプルする。

**グリッドは本当の直線に置く。** 原点から北へ x = 0 の上に 5 点を並べ、スタートラインを
その途中の (0, 65) に置いてある。向心 Catmull-Rom は一直線に並んだ 4 点の中の 2 点の間を
厳密に直線で結ぶので、グリッド (線の手前 6〜37 m) の向きの変化は 0 になる。以前は線を
原点に置いていて、**グリッドが最終右の出口に乗っていた** — その範囲で向きが 30.7°
変わり、グリッドの向きのまま踏むと 3 秒で草に落ちた。

**一様版 (α = 0) を採らない。** ヘアピンの前後で制御点の間隔が急に詰まるので、一様版だと
接線が過大になって**路面が自分と交差する**。向心版はループも尖りも出ないことが分かっている。

**縮尺合わせに反復は要らない。** 向心の節点は点の間隔の**比**しか使わないので、制御点を
k 倍すると節点はすべて √k 倍になって比が変わらず、**曲線は厳密に k 倍の相似形・弧長も
厳密に k 倍**になる。生の長さを 1 度測って割るだけで狙いの 1 周に合う — **実測 1200.0 m**
(狙いは 1,200 m)。

**刻みは 20 単位に固定せず `全長 / 個数` で割り切る。** 固定にすると最後の 1 区間だけ
長さが違い、周回の継ぎ目で曲率が跳ねる。

位置からコース上の (距離・横ずれ) を引くのは**前のフレームの添字の ±8 だけ**を見る。
1 フレームに進むのは最大 8.7 単位で、サンプルの間隔 20 単位より短い — **1 サンプルも
進まない**ので、この窓は過剰に安全である。

### 車はタイヤの横力で曲がる

**動的な自転車モデル**である。舵を切ると前輪の向きと進む向きがずれ (**滑り角**)、
前後のタイヤがそのずれに応じて横へ押し返し、**その 2 つの力で車体が回される**。

```text
前の横力   Ff = −capF · tyre(αf / 8°)
後の横力   Fr = −capR · tyre(αr / 7°)
横の加速   = Ff·cos δ + Fr
回りの加速 = (a·Ff·cos δ − b·Fr) / k²      a = 1.3 m・b = 1.4 m・k = 1.3 m
```

**タイヤの横力は飽和する。** 滑り角が小さいうちは比例して増え、ピーク (前 8°・後 7°) を
越えると頭打ちになる。後輪に 1.15 倍の余裕を持たせてあるので、**限界は前輪で決まる
弱いアンダーステア**になる。前が出せる横 G の上限は `grip` (1.3 G) そのものなので、

| | 半径 | 回れる速さ |
| --- | ---: | ---: |
| ヘアピン | 17 m | **54 km/h** |
| 高速コーナー | 86 m | **120 km/h** |
| 全開のまま (480 単位/s) | **177 m** が最小 | — |

が出る。**コーナーごとの上限速度を手で書いたところは 1 つも無い。** 全開ではヘアピンの
半径の 10 倍の円しか描けないので、踏んだままでは物理的に曲がれない。

止めると前へ、踏むと後ろへ**荷重が移り**、移った側のタイヤが余分に効く。ブレーキを
残して切り込むと鼻が入り、踏みながら曲がると鼻が逃げる。前後の力が横の力を奪う
**摩擦円は甘くしてある** (全制動でも横の 7 割が残る)。

**以前は運動学のモデルだった。** 角速度を舵から直に `clamp(v·tanδ/L, ±grip/v)` で決めて
いたので、向きに慣性が無く、限界でも滑り角が常に 0 で、「レールの上を走り、上限に
当たると見えない壁で止まる」手触りになっていた ([#88](https://github.com/mokume-metal/works/issues/88))。

#### キーで運転するための助け

キーは 0 か 1 しか渡せないので、人の手の細かい操作をいくつか車の側で補う。

- **舵角の上限は速さで絞る** — `atan(L·grip/v²) + 4°` (上限 34°)。キーを一杯に押すと、
  前輪がちょうどピークを少し越える角になる。押しっぱなしでも押し出しは浅い
- **逆舵** — 後輪がピークを越えて滑り出したら、越えたぶんだけ前輪を進む向きへ返す
- **持てない回転を削り、出た尻を戻す** (簡易の横滑り防止) — 引き手を握っている間は切る
  ので、尻は出せて、放せば約 1 秒で立て直す
- **舵の速さ** — 戻しと切り返しは速く、切り込みは速いほど遅く。高速で一気に切れると、
  直線で少し当てただけで跳ねるように向きが変わる
- **遅いときは幾何で曲がる** — 滑り角の式は速さで割るので、止まりかけでは硬くなりすぎる。
  11〜29 km/h で前輪の向きだけで決まる曲がり方へ混ぜ、後退は常にそちらで曲がる

#### 足の下と壁

足の下は中心線からの横ずれだけで決まる。草の最高速は踏み続けたときの釣り合いを解いて
**約 60 km/h** — 「落ちたら損をするが、戻ってこられる」の線である。

**壁は当たった強さだけ返す。** 壁へ向かう速さに反発 (0.25) を掛けて返し、接線には
当たった強さに比例した摩擦だけを掛ける。擦るだけならほとんど何も失わない。当たった角
(鼻か尻) から車体を回し、鼻か尻が壁を向いている間は壁沿いへ向きを寄せる。

### 相手は人と同じ操作しか返せない

AI が返すのは `Controls` 構造体 (踏む・止める・曲がる・引き手) だけで、**物理は誰が
運転しているかを知らない**。「AI だけが余分に曲がれる」ことが構造的に起きないので、
相手が速いとしたらそれは同じ車をうまく操っているからである。

速さを決めるのは**制動距離を織り込んだ後ろ向きの走査**である。

```text
目標速度 = min over Δ ( √( v_corner(κ(s+Δ))² + 2·a·Δ ) )
```

先の曲率から「そこを回れる速さ」を出し、**そこまでに詰められるぶんを足して**今の上限に
する。これが無いと、コーナーの入口で急に止まるか、突っ込んで飛び出すかのどちらかになる。

**ライン取りは手で引いていない。** 広い窓 (±60 m) で均した曲率を横ずれに写すだけで、
**平均の遅れがそのままアウト・イン・アウトになる**。

**ラバーバンド (順位で相手の性能を上下させる) は採らなかった。** 見えないところで
不公平をやると、勝っても負けても納得が残らない。代わりに**全員へ等しく効くスリップ
ストリーム**を置いてある — 前の車の 20 m 以内では空気抵抗の 2 乗の項が 45% 減るので、
長い直線で後ろの車が伸びる。**人が使っても同じだけ効く。**

**舵は純追従の曲率から決める。** 目標点を通る円を回る舵角に、タイヤがずれるぶん
(アンダーステア) を先に足し、狙いの角速度と実際の角速度の差を返す。車は舵で直には
回らない (タイヤが回す) ので、この帰還が無いと高速で蛇行する。

**限界いっぱいは狙わない。** 横 G は腕前 × 0.9、後ろ向きの走査が見込む制動は 0.6 に
してあり、狙う横ずれは路面の端から 2.5 m 内に収める。上限ちょうどで回ると線から
2 m ほど外へ膨らみ、縁石でタイヤの効きが落ちて壁まで流れた。

**前の車には追突しない。** 横に重なっている前の車ごとに、その車の後ろで止まれる速さを
上限にする (這う速さだけは残す)。遅い車が前にいるときは、いつもの線を捨ててその車の
横 (当たりの円の外) を狙って抜く。スタートで出遅れた自分の車に、斜め後ろの相手が
ライン取りで寄って当て、壁まで押し出していた。

3 台の腕前は 0.96 / 0.91 / 0.86 と散らしてある。

### 追うカメラは車に付く

目は車の後ろ、注視点は**車の鼻先のさらに前**に置く。舵を切れば視界が一緒に回り、画面の
奥がいつも車の進む先になる。

以前は注視点をコースの先へ 6 割寄せていた。コーナーでは視線が勝手に内へ回り込んで
見栄えはよかったが、**舵を切っても視界が回らず、車だけが画面の中で回った** — 向けた
先が画面の奥に来ないので、どれだけ切ればよいかが読めなかった。

カメラが居るのは「車の向き」と「進んでいる向き」の**間** (0.3) である。車の真後ろだと
滑るたびに世界が振り回されて酔い、経路の真後ろだと車が画面を横切って滑る。0.3 は
車の向きに寄せた中間で、尻が出れば横腹が少し見え、向けた先は画面の奥に残る。

硬さは時定数で決める。`mix(いま, 狙い, 0.1)` と書くと**速い機械ほどカメラが硬くなる**ので、
`1 − exp(−dt/τ)` の形で追う。

**視野角は 62° から 74° まで速さで広がる。** 速度計を見なくても速さが分かる、いちばん
効く仕掛けである。

### 路面に絵を貼らない

舗装に絵を繰り返し貼ると、**寝た面なので遠くで必ず滲んで踊る** (mokume の `Image` は
縮小の段を持たない)。ここは頂点の色だけで組み、速度感は**縁石の縞** (2 m 周期)・
リングごとの陰の揺らぎ・木立・視野角の広がりで出している。

**縁石の縞はコーナーだけに出す。** 直線の両脇までずっと縞だと、どこが曲がっているのかが
遠目に読めない。曲率が半径 167 m より小さいところは白線になる。

**スタートラインは別の板を重ねない。** リング 0 の路面そのものを市松に割るので、
同一平面の重なりが 1 枚も生まれず、z が競って散ることが原理的に起きない。

## 踏んだもの

### この機械では `mokume run` / `watch` がどの作品でも通らない

[mokume#1268](https://github.com/mokume-metal/mokume/issues/1268)。Xcode 27 (Swift 6.4) の
既定のビルドシステムが mokume の `.metal` を単独でコンパイルして落ちる。**Apex だけで
なく Quarry でも同じところで落ちる**ので、作品側の問題ではない。既知だったので新しくは
起票していない。抜け道は上の「走らせる」のとおり。

### 使う字の種類が増えると、その時点から GPU が 1 フレームも描けなくなる

[mokume#1273](https://github.com/mokume-metal/mokume/issues/1273) に戻した。**手元の表示を
日本語で書いたら、1 フレームも描けなくなった。**

切り分けに 12 回作り直した。効いているのは文字数でも、文字の大きさでも、`text()` を
呼ぶ回数でもなく、**スケッチが使う字の種類**だった。

| 手引きの 2 行に出した文字列 | 新しい字 | |
| --- | --- | --- |
| `"W go S stop"` / `"AD turn R zero"` | W g o S s t p D u r n z e | **13.5 秒で止まる** |
| `"LAP 1 / 3"` を 2 行 (ほかの行と同じ字) | **なし** | 走り続ける |

**止まる地点はコースの同じ場所 (s ≈ 415 m) で、毎回そろっていた。** そのせいで最初は
コースの幾何か、そこで描かれる木か影を疑った — 焼いた頂点を全部数えて壊れた値が
1 つも無いことを確かめ、影も後処理も木も車も地面も 1 つずつ外し、**最後に残ったのが
文字だった**。

日本語が 1 文字で落ちたのも、`textSize` を毎フレーム変えると落ちたのも (**同じ字でも
大きさが違えば別のグリフ**)、長い行で落ちたのも、全部これで説明が付く。

**警告の文面は「描きすぎ」と言う。** 実際には路面 32,538 頂点・木 109 本・車 4 台・影を
全部描いたままでも、字さえ増やさなければ 60fps で走り続ける。逆に**それらを全部消して
文字だけ出しても止まる**。

いま出している字は**数字・`:`・`.`・`/`・`-`・空白・`LAP`・`BEST`・`P`・`km/h`** だけで、
**新しい字を出す場面をすべて畳んだ** — 操作の手引きは README へ移し、着順の `FINISH` は
外した。**着順は 1 度しか出ない場面なので、そこで初めて使う字があると取り返しがつかない。**

合図の `GO` は最初、数字の `1` へ畳んだ。すると**合図が「1 の出し直し」でしかなくなり、
GO の瞬間が読めなかった** — 「1」が消えるのを待ってから踏むと 1.4 秒遅れ、そこへ後ろの
車が来た。いまは字を使わず、**灯の色**で出している (上記「触る」)。逆走の知らせも同じく
字を使わない矢印である。

### `createShape` の中では `push` / `translate` / `rotate` が効かない

組み込みの立体 (`box` / `cylinder`) を変換して焼こうとすると**全部が原点に積み上がる**。
車輪が縦のまま車体に刺さった絵が出て気付いた。車体も路面と同じように頂点を自分で
並べる形にした。

### 世界の y だけを反転すると、絵が左右の鏡写しになる

世界は y 上向きで持ち、mokume の縦は下向きなので、渡す直前に y の符号を変えていた。
**軸を 1 本だけ反転すると鏡映になる** (行列式が −1)。右カーブが画面では左へ曲がり、
**`D` (右) を押すと車は画面の左へ向いた**。右上の地図だけは正しく描けていたので、地図と
3D が食い違っていた ([#88](https://github.com/mokume-metal/works/issues/88))。

いまは**写しを (x, y, z) → (−x, −y, z)** (z 軸まわりの 180° の回転) にして、`Apex.screen`
の 1 か所に集めてある。写しを回転に変えると面の表裏が逆になる (mokume は不透明な面の
裏を捨て、表は画面で時計回り) ので、`form` で三角形ごとに巻きを 1 度だけ裏返す。車の
回転も世界の回転を写しで挟み直して導いた — Y と X の回転は向きが逆になり、Z はそのまま
残る。**鏡映のころは、車の傾きと坂での鼻上げも逆を向いていた。**

**絵を見ても気付かなかった。** 1 枚の絵では左右が裏返っていても道は道に見える。気付いた
のは、曲率が正 (右カーブ) の地点で撮った絵が左へ曲がっていたからである。

### 壁の罰を速度に掛けると、壁から出られなくなる

擦っている間ずっと速度に 0.997 を掛け (1 秒で 3 割)、向きを 1 歩ごとに 2 割ずつ壁沿いへ
寄せていたころは、**壁に貼り付いた**。押し出された先の草で踏み続けても 12 km/h しか出ず、
舵を切らない限り壁から離れなかった。0.985 にしたときは 1 秒で 8 割方削れて止まった。
いまは当たった強さだけ返す (上記「足の下と壁」)。

### 踏まなかったもの — `Placement` の変換順

`Placement` の変換は **T·Rx·Ry·Rz·S** の順に積まれるので、点にはロール → ヨー → ピッチの
順で効く。**ヨーが 90° の車にピッチを与えると、車体はロールする** — コースの向きに
よって車が横に傾くという、見つけにくい壊れ方をする。先に読んで気付いたので、車は
`push / rotateY / rotateX / rotateZ / pop` で置き、`Placement` は**色を掛けるためだけ**に
使っている。ヨーしか使わない木立には `shape(_:at:)` をそのまま使える。
