# Cast — 1 つの塊が、向きによって別の形の影を落とす

![空の床に円の影だけがある。塊はまだ透けていて見えない](https://i.gyazo.com/03a80001bad74bc4b0c812f46bdda74c.png)

制作トラック ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md)) の 12 本目。

**形は物の側ではなく、光の側にある。** 置いてある立体は塊が 1 つと床が 1 枚だけで、絵になっているのはそのどちらでもなく**影**である。塊は読めない形をしていて、決まった向きで止まったときにだけ、床の影が円・三角・四角になる。

11 本目の [Tempo](../Tempo/) は「光を 1 つも置いていない」ことを名乗った作品だった。ここはその裏返しで、**works で影を落とす 1 本目**である。光そのものは Grain・Helmet・Quarry が置いているが、**影の口 (`shadows` / `castShadow` / `receiveShadow` / `shadowRange` / `shadowDetail` / `shadowBias`) と材質の `ambient` は、作品 11 本のどれも通っていなかった**。

![48 秒でひと回りする 4 つの幕](https://i.gyazo.com/bd77a8647994c17175bbaa4b17a33185.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` と同じ観測の区画へ要求を置いて書き出した絵で、画面は撮っていない)。**等速** — 6 フレームおきに撮った 480 枚を、記録された時刻をもとに 0.1 秒の升目へ並べ直した 48 秒である (ずれは最大 0.05 秒 = 半コマ)。幅 720・10fps。

## 48 秒を 4 つの幕で渡る

| 幕 | 秒 | 起きること | その幕でしか見えないもの |
| --- | --- | --- | --- |
| 影 (SHADOW) | 0–6 | 空の床に影だけがあり、塊が透けて現れる | **影は物の不透明さを見ない** — 焼き付けは深さだけを見るので、透明な塊も影を落とす |
| 姿勢 (TURN) | 6–18 | 塊が 3 つの姿勢を渡る | 同じ場所で形だけが入れ替わる |
| 粒 (GRAINS) | 18–32 | 塊が 2,412 個の立方体へ砕け、光の筋に沿って伸び、波打ち、また集まる | **光の筋に沿って動かしても影は動かない** |
| 光 (SUN) | 32–48 | 塊は止まったまま、光の方位が 1 周する | **塊を回すことと光を回すことは同じ** — 床の 3 か所で形になる |

**4 つの幕は 4 つの作品ではない。** どれも同じ 1 つの式の見え方で、色は 4 色・動きはすべて時刻の関数である。**幕 4 が落ち**で、幕 2 では塊を回して 3 つの形を出したのに、幕 4 では**塊を 1 度も動かさずに**同じ 3 つが出る。作品が最初から「光の側の話」だったことが、そこで分かる。

## 走らせる

```bash
mokume run Cast -c release    # 作って走らせる
mokume watch Cast -c release  # 保存したら作り直して差し替える
mokume mcp Cast               # 走っているスケッチを外から観測する
```

**`-c release` で走らせること。** 走り出してからはどちらも 60fps を保つが、**立ち上げが debug では 17 秒**かかる (release は 0.25 秒)。塊を彫るのも影の被覆を数えるのも、最初の 1 フレームで 1 度だけ走る CPU の仕事なので、最適化の有無がそのまま出る (下記「速さ」)。

## 触る

| 操作 | 効くもの |
| --- | --- |
| ドラッグ | **時刻を擦る。** 画面のどこを掴んでも、下の定規と同じ物差しで 0…48 秒へ写る |
| Space | 止める / 動かす |
| ← → | 0.25 秒ずつ戻す / 送る |
| 1 / 2 / 3 / 4 | その幕の頭へ飛ぶ |

**擦ったとき、絵と時刻は必ず一緒に動く。** 別々に動くとしたら、それは絵が時刻以外の何かを覚えているということである。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。** この作品のコミットを checkout すれば mokume も当時の版に戻る。Pond・Quarry・Tempo と同じ `v0.7.1` である。

**同じ時刻からは同じ絵が出る。** 時刻を渡すと ``Score.Frame`` が決まり、そこから下は時計を読まない (塊の姿勢・光の方位・粒の散り方・カメラの引きが全部その構造体に入っている)。乱数も雑音も使わず、`frameCount` も読まない。

**ひと回りしたら同じ絵に戻る。** 継ぎ目 (`t = 47.97` と `t = 0`) の絵を突き合わせると、**計器の数字を除いた場面は PSNR 103.8 dB** — 方位が 2π と 0 で浮動小数の下位ビットだけ違う。

## 何がどう動いているか

### 影は「高さに比例した平行移動」でしかない

向きを持つ光の下では、点の影は次の式で決まる。仰角 φ・方位 α の光で、高さ `Y` の点 `(X, Z)` が床へ落ちる先は

```text
影 = (X, Z) + κ·Y·e(α)        κ = cot φ
```

**この作品の出来事は全部ここから出る。**

| 動かし方 | 影はどうなるか | どの幕 |
| --- | --- | --- |
| 縦軸まわりに回す | 形が変わる (`κ·Y·e` の項が回らないため) | 幕 2 |
| 光の進む向きに沿って動かす | **何も起きない** | 幕 3 |
| 水平に動かす | 同じだけ動く | — |
| 方位 `e` を α 回す | 「塊を α 回した絵」を床の上で α 回したものになる | 幕 4 |

光を真上から差すと `κ = 0` になってずれが消え、**3 つの影は完全に同じ絵になる** — 作り分けは原理的にできない。この作品が斜めの光でしか成り立たない理由である。

### 彫り出しは「3 つとも内側」だけを残す

塊は距離の関数で決まる。

```text
f(p) = max_j  d_j( σ_j(p) )          j = 0, 1, 2
塊 = { p : f(p) ≤ 0 }
```

`d_j` は姿勢 `j` で狙う図形の符号付きの距離、`σ_j` は姿勢 `j` で回してから床へ落とす写像である。「3 つとも内側」という条件を、そのまま「3 つの距離のうちいちばん大きいもの」として書いただけである。

**はみ出しはここから構造上ゼロになる。** 塊の点はすべて `f ≤ 0` を満たし、それは「3 つの姿勢のどれで落としても狙いの内側」という意味なので、**影が狙いの外へ出ることは定義から起きない**。起こるのは欠けだけである。

### 欠けは三角形の角から出る

3 つの狙いは**面積をそろえてある**。そろえないと、いちばん小さい図形が他の 2 つを削り落として全体の被覆を下げる。等面積にすると寸法はこうなる:

| 図形 | 寸法 | 外接半径 | 内接半径 |
| --- | --- | --- | --- |
| 円 | `r` | `1.00 r` | `1.00 r` |
| 正三角形 | 一辺 `2.694 r` | `1.555 r` | `0.778 r` |
| 正方形 | 一辺 `1.772 r` | `1.253 r` | `0.886 r` |

**三角形の角は円より 1.55 倍遠い。** 円の影に収まる点しか残せないので、三角形の 3 つの角がいちばん埋まりにくい。実測 (立ち上げに 1 度数える・`Cover`) がそれをそのまま出している:

| 姿勢 | 狙い | 埋めた割合 | はみ出し |
| --- | --- | --- | --- |
| 0° | 円 | **96.89%** | 0 |
| 120° | 三角 | **91.95%** | 0 |
| 240° | 四角 | **93.86%** | 0 |

はみ出しは床へ敷いた格子 (256 × 256・1 画素 2.6 単位) で数えていて、**縁の 1 画素ぶんは量子化の誤差として見逃している**。「構造上ゼロ」を保証しているのは式のほうで、この数は**式のとおりに書けているかの検算**である (0 でなければ写像か距離が間違っている)。

![120° で三角の影が立つ](https://i.gyazo.com/ee22b3769fd88d4289892291fdc3c37a.png)

> 撮影範囲: 観測が書き出した絵 (幕 2・拍 9.99 秒)。朱の輪郭が狙いで、影との差がそのまま上の表の「欠け」である。三角形の角が少し丸いのが見える。

**向きは掃いて決めた。** 三角形と正方形の向きを 10° 刻みで動かし、ずれの総量 `T` も 3 通りで回して、3 つの狙いの最小被覆がいちばん高くなる組を選んだ (使い捨ての探索を別に書いた・作品には測る口を持たせない)。**どこを選んでも 89–92% の帯に収まり**、いちばん良い組でも 92.35% だったので、**調整の出来不出来には賭けていない**。

### 面は箱を積まずに切り出す

塊は 370 万個の節に並べた `f` から、**符号が変わる辺を見つけて面を張って**いる (surface nets)。セルの箱をそのまま積む Quarry のやり方だと、塊の階段がそのまま影の階段になり、**影が主題の作品では狙いの図形の輪郭が段々になって出てしまう**。

法線は `f` の傾き (中心差分) から取る。**面ごとではなく節ごとに向きが決まる**ので、光の当たり方が連続に変わり、細かい面がモアレにならない。焼いた形は **72,028 枚の三角形 (216,084 頂点)** で、毎フレームの描画回数は **1** である。

### 粒は立方体を 1 つ焼いて置き場所を配る

幕 3 の塊は **2,412 個の立方体 (一辺 22)** でできている。`shape(_:at:)` は置き場所をいくつ渡しても**描画が 1 回**で済むので、千を超える粒でも塊 1 つより軽い。

**粒でもはみ出しは出ない。** 残すのは「立方体の 8 隅がすべて `f ≤ 0`」のセルだけで、塊は凸なので 8 隅が内側なら立方体まるごとが内側にある。細かさが落ちるぶん影の縁は粒の大きさだけ内へ入る (砕けた瞬間に影が少し痩せる) が、**狙いの外へ出ることは粒でも起きない**。

![粒が光の筋へ伸びても、床の影は動かない](https://i.gyazo.com/1433e4e39b7486c7819e6afa0ebc6b70.webp)

> 撮影範囲: 観測が書き出した絵。**等速** — 2 フレームおきに撮った 120 枚を幅 720・30fps で並べた 4 秒 (20.04 秒から 24.01 秒)。粒が斜めへ長く伸びていく間、**床の円は 1 ミリも動かない**。

**動かし方は 2 つだけ**で、どちらも上の表の「何も起きない」に当たる動きである — 光の筋に沿って伸ばすことと、同じ筋に沿って波打たせること。**影がどう振る舞うかを先に知ったうえで選んだ動き**で、粒を勝手な向きへ飛ばすと影はただ散らかる。

止まったまま 2 秒ぶん離れた 2 枚 (`t = 24.51` と `t = 26.49`) から、**床だけを 380 × 380 で切り出して md5 を突き合わせた**: `e4cb8320…` で**1 バイトも違わない**。粒は動いていて、影は動いていない。

### 光を回すことと、塊を回すことは同じ

幕 4 は塊を止めたまま光の方位を 1 周させる。影は塊の真下のまわりを大きく掃き、**3 か所で形になる**。式で書くとこうなる (`c(α)` は影の中心・`R_α` は床の回転):

```text
影(姿勢 θ, 方位 α) = c(α) + R_α[ 影(姿勢 θ+α, 方位 0) − c(0) ]
```

つまり方位を 120° 回すと、**塊を 120° 回したときの形**が、**床の上でも 120° 回った場所と向き**で出る。幕 2 と幕 4 で形の出る順番が逆になる (円 → 三角 → 四角 に対し 円 → 四角 → 三角) のはこのためである。

![方位 120° で三角の影が立つ](https://i.gyazo.com/248118c7612778ee1dc84f6fa7bddd4e.png)

> 撮影範囲: 観測が書き出した絵 (幕 4・36.99 秒)。塊の姿勢は 0° のまま、光だけが 120° 回っている。朱の輪郭は上の式から置いた位置と向きで、**影とぴったり重なる**。

### 光は 1 本しか置かない

mokume で影を落とすのは**向きを持つ光の 1 本目だけ**である。点光源もスポットも、置けば明るくはなるが影は落とさない。影が主題なので 2 本目は置かない — 足すと、影を落とさない光が絵を持ち上げて影の濃さだけが薄くなる。

**影の濃さを決めているのは底上げの光と、床がそれをどれだけ返すかである。** 影が薄くするのは向きを持つ光のぶんだけなので、底上げのぶんがそのまま影の明るさになる。

### 影の焼き付けはフレームの終わりに 1 度走る

焼き付けは「光から見た平行投影」で、中心は**いまのカメラの注視点**、一辺は `shadowRange`。切り取った外は「遮られていない」として返るので、**足りないと影が切れる**。幕 3 では粒が光の筋へ伸び、幕 4 では影が大きく回るので、**箱の大きさは毎フレーム計算し直している** (2,464〜3,690 単位)。

わざと 420 単位まで絞ると、三角の影が中央の小さな切れ端だけになる — 絵が暗くなるのではなく、影が四角く削げる。

**手元の表示のために `noLights()` を呼んでそのまま終えると、そのフレームの影が丸ごと消える。** 焼き付けはフレームの終わりに 1 度だけ走り、**そのときの光**を読むためである。ここでは光を消さずに手元の表示を描いている (下記「踏んだもの」)。

## 速さ (2026-09-13 の実測)

Apple M3 Max / macOS 26 / mokume `v0.7.1` / 1920 × 1080。

| | release | debug |
| --- | --- | --- |
| 彫り (370 万節へ `f` を並べる) | 15.2 ms | 3,993 ms |
| 焼き (面を切り出して 1 つの形へ・粒を拾う) | 108.8 ms | 5,327 ms |
| 数え (3 つの姿勢の被覆) | 111.9 ms | 7,745 ms |
| **立ち上げ合計** | **0.24 秒** | **17.1 秒** |
| 走り出してからの fps | 60.0 | 60.0 |

**70 倍の差が出るのは、立ち上げの仕事が全部 CPU にあるからである。** 走り出してからは GPU の仕事しか残らないので、debug でも 60fps を保つ。どの幕でも 60.0fps・1 フレームの最大 16.7–20.9 ms (観測しながらの値) で、記憶は 690 MB 前後。

## 直したこと

### 光を回したとき、輪郭だけが別の場所に出た

手引きの輪郭を「塊の姿勢 − 光の方位」で選んでいた。正しくは**和**である (上の式)。**方位 0 では気付けない** — 円は回しても円なので、幕 2 だけ見ていると合っているように見える。幕 4 で四角の輪郭の上に三角の影が出て、初めて符号が違うと分かった。**手引きが影とぴったり重なるかどうかが、この式の検算になっている。**

### 星の模様を作ろうとして、角の丸い斑になった

粒を光の軸のまわりに回せば「影も同じ角だけ回る」と考えて、三角を 60° 重ねた六芒星を作ろうとした。**回らない。** 影への写像は光に直交する面から床への線形写像で、床が傾いているぶん一方向に伸びる — 相似ではないので、回転を挟むと `A R A⁻¹` という「傾いた回転」になり、円は楕円へ潰れる。出たのは星ではなく角の丸い斑だった。**幕 3 の動きは、影が素直に従う 2 つ (筋に沿った平行移動と波) だけに絞った。**

### 段に切って横へずらしても、縞にならなかった

同じく幕 3 で、群れを 9 段に切って横へ開けば影が縞に割れると考えた。**段の影は三角の切れ端ではなく、塊の断面まるごとの影**なので、重ねても縞にならず崩れた斑になる。分けるなら塊まるごとを分けるしかない。

### 光の方位が、最初から 240° になっていた

方位の譜を「区間ごとの到達角の `max`」で書いていたので、**まだ始まっていない区間の基準角が先に効いた**。足し合わせる形に直した。

### 立ち上げの絵が「影だけ」にならなかった

塊の濃さが 0 のときに描画ごと飛ばしていたので、影まで消えた。**透明でも影は落ちる**ので、濃さとは別に「そこに在るか」を持たせて、幕 1 は在るけれど透明な塊として描いている。

### 粒が画面の外へ出た

光の筋に沿って塊の高さの 2.6 倍まで伸ばしていたので、群れが画面から溢れた。1.7 倍へ詰め、伸びるぶんだけカメラを引くようにした (引きも時刻の関数)。

## 踏んだもの

1. **フレームの終わりに `noLights()` を呼ぶと、そのフレームの影が黙って消える。** 手元の表示を「既定のカメラ + `noLights()`」で描く形は mokume の参照スケッチにも Quarry にもあるので、**影を使う作品と手元の表示を同時に持つと必ず踏む**。mokume へ戻した ([#1151](https://github.com/mokume-metal/mokume/issues/1151))
2. **光の強さの尺度が 2 つある。** 数値で渡す口は塗りと同じ 0…255、`LinearRGBA` の口は 0…1。**間違えたときに出るのが真っ黒な絵**なので気付きにくい。mokume へ戻した ([#1152](https://github.com/mokume-metal/mokume/issues/1152))
3. **透明な立体も影を落とす** (焼き付けが深さだけを見るため)。幕 1 はこの性質の上に立っている
4. **観測の区画は走っているスケッチの数だけ取り合う。** debug の計測のために 2 つ目を走らせたまま `observe` を呼び、古いほうの絵と数字を読んでいた。報告の `stamp` を作り直した版と突き合わせれば気付ける

**踏まなかったもの**: `shape(_:at:)` は 2,412 個の置き場所でも描画 1 回に収まり、置き場所ごとの塗り (`Placement.fill`) は立体にも掛かった。`plane` は `rotateX(π/2)` で寝かせればそのまま影を受けた。`shadowDetail(4096)` は素直に効いた。
