# Pond — 池の水面と錦鯉

![風の斑が渡っている池。錦鯉 6 匹が泳ぎ、水面の傾きが底を歪め、太陽のきらめきが散る](https://i.gyazo.com/816ee680d45338fb341edfbcd98edce7.png)

制作トラック ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md)) の 9 本目。

**水っぽく描くのではなく、水面の傾きから絵を導いている。** 高さ場 `h(p, t)` を持ち、その勾配 `∇h` だけを絵に使う — 屈折も焦線も鏡面反射も、全部そこから出る。だから**凪いでいるあいだは傾きが小さく、底の砂利が歪みなく見える**し、風の斑が渡れば底が崩れて代わりに面がきらめく。

既存 8 本が通していない経路が 3 つあった。**面を 2 枚焼いて断片から名前で読む**こと、**CPU が書いた数を断片が読む**こと (`Numbers` の CPU 書き込み)、そして **2D の頂点に形自身の座標を持たせて模様を貼る**ことである。3 つ目は素直には通らず、抜け道で通して [mokume#1140](https://github.com/mokume-metal/mokume/issues/1140) へ戻した。

![餌を落としてから鯉が寄って食べるまでの 5.2 秒](https://i.gyazo.com/5b1492d27b2b89056d9ce408ff9ea953.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵で、画面は撮っていない)。餌を 1 粒落とした直後から 5.2 秒ぶんを 4 フレームおきに 78 枚取り、幅 720・15fps にしたもの (等速)。**1 枚では読めないものを見てほしい** — 落ちた輪が広がりながら底を歪ませ、離れていた鯉が向きを変えて寄り、口が届いたところで餌が消える。輪の**峰が後ろから湧いて前で消えて**いくのは、包絡が群速度で・峰が位相速度で動いているためである (下記)。

## 走らせる

```bash
mokume run Pond -c release    # 作って走らせる
mokume watch Pond -c release  # 保存したら作り直して差し替える
mokume mcp Pond               # 走っているスケッチを外から観測する
```

**`-c release` を付ける。** `run` / `watch` の既定は debug で、そこでは 43.7fps まで落ちる (下記「速さ」)。

## 触る

| 操作 | 効くもの |
| --- | --- |
| クリック | **餌を落とす。** いちばん強い輪が広がり、鯉が寄って食べる。消えるのは**口へ届いたときだけ**で、食べた場所にも小さな輪が出る |
| マウスを動かす | **水面を撫でる。** 指の跡に沿って輪が出て、**鯉は逃げる** (1.6 秒かけて怖さが引く) |
| スペース | 餌を片付ける |
| R | はじめへ戻す (餌と輪を消し、**風の時計を起動時へ戻す**) |

**風はつまみではない。** ここに風の操作は無く、待っていると渡ってくる (下記)。

### 風はたまに渡っていく

| 凪 (風 0.05) | 斑の下 (中央で風 0.75) |
| --- | --- |
| [![](https://i.gyazo.com/4ba8496c61c244d1e7b1f9f079a67e96.png)](https://i.gyazo.com/4ba8496c61c244d1e7b1f9f079a67e96.png) | [![](https://i.gyazo.com/f5283414f9fbabfc8d0e2a451a96f1d8.png)](https://i.gyazo.com/f5283414f9fbabfc8d0e2a451a96f1d8.png) |
| 砂利の輪郭が出る。焦線も薄く、太陽は**1 枚の玉**として映る | 底が読めなくなり、代わりに面じゅうに**きらめきが散る** |

**面が傾かなければ、屈折も焦線もきらめきも出ない。** 3 つとも同じ `∇h` から出ているので、風が抜ければ同時に薄くなる。**太陽の玉が凪のときだけ丸いのも同じ理由**で、面が平らなら反射の向きが揃い、傾きがあれば向きが散って玉が粒に割れる (これが「きらめき」の正体である)。

**この 2 枚は設定の違いではなく、同じ池の別の時刻である。** 風は面のどこでも同じ数ではなく、**渡っていく斑** — 凪いだ水に弱い風が当たると、当たったところだけが細波で暗くざらつき、その斑が風下へ抜けていく (英語で cat's paw と呼ぶ)。平均 35 秒に 1 度、どこかの縁から入って池を横切る。

![風の斑が池を横切る 13 秒](https://i.gyazo.com/f54ba86ce092988a2378cd29cd2e7e5f.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵で、画面は撮っていない)。斑が生まれる直前から 13.3 秒ぶんを 3 フレームおきに 100 枚取り、幅 720・7.5fps にしたもの (等速。debug で走らせたまま撮ったので、コマ数はこれが上限だった)。**1 枚では読めないものを見てほしい** — 斑の前縁が入ってきて面がざらつき、抜けたところから底が澄んでいく。中央で測った風は 0.05 → 0.45 → 0.05 と動いた (`mokume mcp` が読める `wind`)。同じ風の場が花びらと睡蓮も押しているので、斑の下では浮いているものの流れも速くなっている。

**斑は風速そのもので渡る** (300〜520 mm/s)。猫の足跡が出るのは Beaufort 1 (0.3〜1.5 m/s) の弱い風なので、その速さになる。細波の峰はそれより速い (22 mm の波で 235 mm/s、長い波はもっと速い) から、**斑の中で生まれた波が前縁から抜け出していく** — 置いた数ではなく、分散関係と風速を別々に入れた帰結である。

**前縁は狭く、後縁は長い。** 風が当たった面はすぐざらつくが、抜けた後の細波は減衰に時間がかかるので、斑は後ろへ尾を引く (輪の包絡が前後で幅を変えているのと同じ理由)。**斑の中もむらである** — 620 mm の長い揺らぎで削ってあるので、帯の縁が定規で引いた線にならない。

**凪でも 0 にはしない** (0.05 を残してある)。完全な 0 は鏡としては正しいが、絵としては止まって見える。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。** この作品のコミットを checkout すれば mokume も当時の版に戻る。

**works で最初の `v0.7.1` である** — ほかの 8 本はまだ `v0.7.0` を引いている ([#49](https://github.com/mokume-metal/works/issues/49) が追随を追っている)。`Package.swift` は `from: "0.7.0"` と書いてあり、作った日にそこから解決されたのが `0.7.1` だった。

**同じフレーム番号からは同じ絵が出る** (mokume の [ADR-0001](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0001-founding-principles.md) 原則 2)。この作品は乱数を使わない — 砂利と水草と睡蓮の配置は、種を持った自前の並び (`Scatter`) が起動時に 1 度だけ決める。**風の斑も同じ**で、「何番目の斑か」から種を作るので、いつ引いたかに依らず時刻だけで決まる (賽を振って持ち越すと、引く回数がフレームの刻みで変わり、速い機械ほど風の吹く池になる)。**触っていない限り、同じ番号のフレームは同じ絵になる。**

**絵のハッシュは持っていない**ので、版を上げて何かが動いたことに気付くのは窓を開けて目で見たときである。

### v0.9.0 で動いたもの — 測れなかった

**`v0.7.1` → `v0.9.0` の差は、走らせるたびの差と区別が付かない。** 1920x1080 の 83.8〜93.8% が動き、差の平均は 1.3〜2.6 / 255。ところが**同じ `v0.9.0` で 2 回撮っても 84.6〜86.9% が動き、平均は 1.8〜2.4** — 床のほうが大きいフレームもある。

**上の「触っていない限り、同じ番号のフレームは同じ絵になる」は、時計を `frameIndex` にしたときの話である。** 窓を開けて走らせるときの既定は実時間 (`Clock.wallClock`) なので、**フレーム番号を揃えても時刻は揃わない** — 風の斑も鯉の泳ぎも時刻の関数なので、1 フレームぶんのずれが水面ぜんたいに広がる。この作品は「高さ場の傾きだけを絵にする」ので、傾きが少し違えば屈折も焦線も反射も同時に動く。

**ビルドが通り、57fps で走り、水面も鯉も出ることは確かめた** (観測の目録に警告なし)。絵が動いたかどうかは窓を開けて目で見るしかない、という但し書きはこの版上げでもそのまま残る。

## 何がどう動いているか

### 尺度を決めてある — 1 画素 = 1 mm

画面 1920 画素は **1.92 m の池**で、波長も水深も鯉の体長もその尺度の実寸である。尺度を決めたので、**波の速さを手で置かずに済む**:

```
c(λ) = √( g/k + (σ/ρ)·k )      k = 2π/λ
```

水の定数 (g = 9810 mm/s²、σ/ρ = 72800 mm³/s²) をそのまま入れると、位相速度は **λ = 17.1 mm で最小の 231 mm/s** を取る。雨粒の輪がどれも同じくらいの速さで広がって見えるのはこの谷のせいで、置いた数ではなく式から出てくる。

| λ (mm) | 22 | 38 | 66 | 112 | 190 | 330 |
| --- | --- | --- | --- | --- | --- | --- |
| 位相速度 `c` (mm/s) | 235 | 267 | 332 | 423 | 547 | 719 |
| 群速度 `c_g` (mm/s) | 206 | 179 | 187 | 221 | 278 | 361 |

### 絵にするのは高さではなく傾きである

真上から静かな水を見ても高さは見えない。見えるのは「傾いた面がどこを映し、どこを透かしているか」だけなので、水面が外へ渡すのは `h` ではなく `∇h` になる。

- **屈折** — 法線 `n = (−∂h/∂x, −∂h/∂y, 1)` と視線から Snell (`refract`) で水中の向きを出し、深さぶんだけ読み位置をずらす。**平らな水面での見え方を基準に、波のぶんだけ**取る (隅では視線が斜めなので、引かないと波が無くても絵が歪む)
- **焦線 (caustics)** — 上の写像のヤコビ行列式そのもの。底へ落ちる像の面積比が `det J` で、明るさはその逆数である。**屈折を止めれば焦線も消える**のが式として繋がっている
- **鏡面反射** — Schlick のフレネル (F0 = 0.02)。**真上から見た水の反射率は 2% しかない**ので、見えるのは太陽だけ。それで十分に光る — 太陽の輝度が桁違いだからで、水面がきらめく理由がそれである

**勾配は解析微分で出している。** 有限差分にすると隣り合う画素で傾きが階段になり、鏡面反射がその折れを拾って面じゅうがギラつく (太陽の玉が点ではなく格子に映る)。

### 平面波の重ね合わせをやめた

はじめは**向きと波長の違う進行波を 14 本重ねて**いた。式としては正しいのだが、**焦線が斜めの格子として整然と並び、池の底が織物に見えた** (同じ大きさの明るい斑が、一定の間隔で斜めに並ぶ)。有限個の平面波の和は準周期なので、位相をずらしても向きを ±80 度まで散らしても、格子がずれるだけで消えない。実際の水面は**波数が連続で、位相が場所ごとに無関係**である。

いまは**尺度ごとの格子の揺らぎ**を 6 枚重ねている (22〜330 mm)。繰り返しが無く、しかも**尺度ごとに自分の波長が要求する速さで流れる** — 上の表のとおり、22 mm の細波は 235 mm/s、330 mm のうねりは 719 mm/s で走る。峰が風に直交して伸びるよう、風向きの座標へ回してから横方向だけ 0.62 倍に潰してある。

**向きは 1 つに揃えていない。** 尺度ごとに ±0.37 rad ずらし (実際の風波は向きに広がりを持つ)、風向きそのものも周期の噛み合わない 2 つの正弦で ±0.35 rad ゆっくり首を振る。揃えていたときは、面が**斜めの畝を並べた布**に見えた。**流れの掃引は軸に沿ったスカラーとして引いてある** — `p − d·(速さ·t)` の形で書くと、向きがわずかに回っただけで長いベクトルの先が大きく振られ、格子が横へ飛ぶ。

揺らぎは**値と傾きを一度に返す自前のもの** (`pond_swell`) である。mokume の `mokume_noise` は値しか返さないので、傾きを取るには隣を引くことになり、上に書いた階段が出る。

### 峰は包絡の後ろから湧いて、前で消える

[![餌を落とした輪と、寄ってくる鯉](https://i.gyazo.com/03d808c8710c530ec19d7bdc4e784e0a.png)](https://i.gyazo.com/03d808c8710c530ec19d7bdc4e784e0a.png)

輪の広がる速さは**群速度**、峰の走る速さは**位相速度**で、この波長域では後者が前者の 1.7 倍ある (λ = 58 mm で 314 / 182)。だから波束の中で峰が前へ追い越していき、先頭で消える。**足した細工ではなく、`c` と `c_g` を別々に使った帰結**である。

輪を置くのは 4 つ: 落ちた餌 (振幅 4.0 mm・λ 58)、食べた瞬間 (1.8 mm・λ 36)、撫でた指 (1.3 mm・λ 46)、そして**鯉が尾を打つたび** (λ 78)。航跡は描いていない — 打つたびに置いた輪が後ろへ残るので、結果として V 字に見える。

**尾の輪だけは深さで薄まる。** 尾が置いていく渦は体の幅ほどしかないので、**体 1 つぶん沈めば水面はもう動かない** (`(0.75 + 速さ × 0.0045) × exp(−深さ ÷ (体長 × 0.45))` mm)。薄まりの尺度が体長なのは、大きい鯉ほど大きな渦を置いていくためで、30 mm に浮いた 368 mm の鯉では 0.83 倍、240 mm に沈んだ 232 mm の鯉では 0.10 倍になる。**立たない輪 (0.30 mm 未満) は置かない** — 32 本の枠を見えない輪が埋めると、餌を落とした輪のほうが押し出される。

### 3 枚の面を 1 枚にする

| 面 | 中身 | 深さ |
| --- | --- | --- |
| `Bed` (960×540) | 砂・砂利 240 個・水草・**鯉と睡蓮の影** | 420 mm |
| `School` (1920×1080) | 鯉の体と鰭だけ。背景は透明 | 84 mm |
| `Surface` (1920×1080) | 睡蓮・花びら・餌。背景は透明 | 水の上 |
| 主面 | 上の 3 枚を名前で読み、水面の断片が 1 枚に合成する | — |

**深さごとに屈折のずれが違う**ので分けてある。底と鯉が別々に揺れることが、この絵の奥行きになっている。底が半分の解像度なのは**水越しの底は暈けてよい**からで、線形補間の甘さがそのまま暈けになる。

濁りは Beer-Lambert で、**行きと帰りの 2 倍の道のり**を通る。赤から先に失われるので深いほど緑へ寄る (底で赤 28% / 緑 63% / 青 42% が残る)。**匹ごとの深さの差**は水面の断片ではなく、鯉を描くときに焼き込んである。

### 浮いているものも、水面の断片が受け持つ

睡蓮・花びら・餌は**もう 1 枚の面へ描き**、水面の断片が最後に重ねる。水越しに見ていないので屈折も濁りも掛からないが、代わりに 2 つが効く。

**横へ流されるぶん。** 深水波の水粒子は円を描く。高さが `a·cos(kx − ωt)` なら横の変位は `a·sin(kx − ωt)` で、**傾き `∂h/∂x = −a·k·sin` を `−1/k` 倍するとちょうどそれになる。** だから傾きさえ持っていれば横の動きは別に数えなくてよい (Gerstner 波が使うのと同じ関係)。**自分より短い波は外す** — 睡蓮の葉は 200 mm ほどあるので、22 mm の細波はその下をすり抜けていく (`Water.floatFollows` が下限)。輪も乗せてあるので、**落とした餌は自分が立てた輪に揺られる。**

**濡れた葉の照り。** 面の傾きから鏡面反射を出すので、**照りが葉の上を細い帯として流れる。** 山を広く取ると葉が一枚まるごと灰色に飛ぶので、鋭い山 (指数 260) を小さく乗せてある。

**葉そのものは茎に吊られた振り子である。** 風に押されて風下へ寄り、戻ってくる。角振動数は振り子の式 `√(g/L)` そのままで、長い茎ほどゆっくり大きく振れる (水中では浮力が重力をほとんど打ち消すので `g` は 14 分の 1。周期は 3.2〜4.9 秒)。**波の 1 つ 1 つが与える捻りは数えていない** — 高さ場は断片の中にしかなく、CPU 側へ写せば式が 2 か所に住む。

![睡蓮が茎に吊られて振れる 5 秒](https://i.gyazo.com/859c454c064b05b88f039913cebaf28a.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。5 フレームおきに 60 枚取り、幅 960・12fps にしたもの (等速)。右下の葉は**左端が 2.8 秒かけて 80 画素往復する** (実測)。葉の上を照りが流れるところと、花びらが波に乗って動くところもあわせて見てほしい。

### 鯉

背骨は**引かれる鎖**で作る。頭だけが自分で進み、後ろの節は前の節から一定の距離で引かれるので、曲がれば体が後から湾曲する — 旋回の形を手で書かなくてよい。そこへ頭から尾へ進む波を重ねる。**泳ぎの波は推進の原因ではなく、進んだ結果へ後から足している** (ここは物理ではなく約束である)。

**寸法は全部体長に対して置いてある。**

| | |
| --- | --- |
| 巡航の速さ | 体長の 0.45 倍 / 秒 |
| 尾を 1 打ちで進む距離 | 体長の 0.45 倍 (鯉は効率のよい泳ぎ手ではない) |
| 尾の振れ幅 (片振幅) | 体長の 5〜6% |
| 振れの伸び方 | 頭からの距離の 1.6 乗 |
| 最小旋回半径 | 体長の 1.3 倍 |
| 最大の幅 | 体長の 0.24 倍 (実測。頭から 30% のところ) |
| 目 | 鼻先から体長の 9%・径は体長の 2.6% (実測) |
| 突進の速さ | 体長の 2.4〜3.2 倍 / 秒 |
| 翻るときの転回 | 最大 150 度 (C スタートの実測値) |

### たまに何かが起きて、また静かに戻る

**ゆったりしているだけでは、長く映したときに同じ絵が続く。** 巡航に緩い揺れを足し続ける
だけだと、速さが変わるのは餌・手・仲間との詰まりに反応したときしかない。

いまは 3 つの層で時間に緩急がついている。

**1 匹ごとの出来事。** 平均 240 秒に 1 つ (6 匹なので**池全体では 40 秒に 1 つ**)、
4 つのうちどれかが起きる。予定は風の斑と同じで「何番目の出来事か」から種を作るので、
**時刻だけで決まる**。

| | 中身 |
| --- | --- |
| **突進** | 体長の 2.6〜3.2 倍 / 秒へ一息に上げて 0.6〜1.1 秒。抜けた後はゆっくり惰行する |
| **翻る** | 突進に**最大 150 度の転回**を重ねる。最初の 0.22 秒だけ首を振れる速さの縛りを外す |
| **漂う** | 体長の 0.1 倍 / 秒まで落として 3〜6 秒。尾はほとんど止まり、胸鰭だけが漕ぐ |
| **渡る** | 体長の 0.8〜1.0 倍 / 秒で 4〜8 秒、さまよわずまっすぐ泳ぐ |

![鯉が突進して翻る 14 秒](https://i.gyazo.com/d4e907af0bcced1905613541cf6173a3.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。3 フレームおきに 100 枚取り、幅 720・7fps にしたもの (等速)。**14 秒のあいだに突進が 2 回**あり、`fastest` (いちばん速い鯉の体長 / 秒) は 0.38 → 2.34 → 0.73 → 2.77 → 0.38 と動いた。**立ち上がりが鋭く、戻りが長い**ところを見てほしい — 抜けた後は普通の減速でゆっくり惰行する (burst-and-coast)。

**突進は伝わる。** 体長の 2.2 倍以内にいる仲間は驚いて、その相手から逸れながら速さを
上げる。魚群の逃避は隣へ伝わるもので、これがあると「1 匹の出来事」が「群れの出来事」に
なる。

**群れの活気。** 池全体の勢い (0.66〜1.34) が数分かけて静と動を行き来する。巡航の速さと
さまよいの幅に掛かるほか、**活気の低い数分は出来事そのものが流れる** — 本当に静かな
時間ができる。

### 餌に食いつく瞬間だけ跳ねる

近づくほど減速する (餌の周りを回り続けた過去の対処。下記) のはそのままで、**餌まで体長の
0.3 倍・正面 25 度以内に入ったときだけ**、体長の 1.6 倍 / 秒へ一息に詰める。狙いが付いて
からしか出ないので、回り続ける挙動には戻らない。

![餌に食いつく瞬間の跳ね 7 秒](https://i.gyazo.com/72c7c4ae8b6f716c9211ac5ef9e590c1.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。3 フレームおきに 50 枚取り、幅 720・7fps にしたもの (等速)。餌を 3 粒落とした直後。速さが 0.53 → 1.41 体長 / 秒へ跳ね、その 0.3 秒後に `pellets` が 3 から 2 になる。

### 鯉は上下にも動く

**深さを固定していない。** 落ち着き先を中心に、周期の噛み合わない 2 つの正弦で 30〜240 mm を
ゆっくり漂う (毎秒 22 mm まで)。餌へ向かうときは浮き、漂うときは沈む。効くのは 3 つ:

- **濁り** — 沈むと水の色へ溶ける
- **影** — 底へ落とす影が横へずれ、縁が広がる (半影は深さに比例する)
- **避け合い** — 体の厚みより深さが離れた組は、重なって見えても上を通り抜けられる

**層の入れ替わりが起きる**ので、長く見ていても同じ重なりにならない。

**真上から見た体の幅は、この作品でいちばん形が出るところである。** 錦鯉はもともと上見で
鑑賞する魚で、頭の丸みと肩の張り、尾筒の太さで見る。

### 群れは 4 つの決まりで間合いを取る

鯉同士は Boids の 3 則 (離れる・揃える・寄る) に、**すれ違いの先読み**を足した 4 つで動く。

| | 何をするか | 効く範囲 |
| --- | --- | --- |
| 離れる | 近すぎる仲間から押し返される | 互いの半幅の 4.0 倍 |
| 揃える | 近くの仲間と向きを合わせる (弱く) | 体長の 2.4 倍 |
| 寄る | 群れの真ん中へ引かれる | **独りになったときだけ** (いちばん近い仲間が体長の 1.6 倍より遠い) |
| 先読み | 最接近の時刻と隔たりを出し、擦れ違えないなら**いまのうちに**逸れる | 2.6 秒先まで |

**4 つ目が要るのは、曲がれる速さに上限があるからである。** 最小旋回半径が体長の 1.3 倍なので、巡航中に首を振れるのは毎秒 20 度しかない。押し返す力だけで組むと反応が始まるのは触れる直前で、そこから避け始めても間に合わず、**重なってから離れる**という見え方になる。相対速度 `v` と相手への向き `d` から最接近の時刻 `t = (d · v) / |v|²` を出しておけば、2.6 秒前から毎秒 20 度ずつ曲げられるので、ゆっくり逸れるだけで擦れ違える。**避けているように見えるかどうかは、力の強さではなく「いつ始めるか」で決まる。**

**間合いは頭同士では測らない。** 鯉は点ではないので、頭が 270 mm 離れていても体長 344 mm の横腹は平気で重なる。測っているのは自分の鼻先と**相手の背骨のいちばん近いところ**である。

**曲がりきれないぶんは速さで詰める。** 前を塞がれている量に応じて巡航速度を落とす。**曲がれる速さは泳ぐ速さに比例するので減速は舵を弱める**のだが、差し迫ったときだけ首の上限を毎秒 55 度まで緩めてあるので相殺される — 魚が遅いところで体ではなく鰭で向きを変えるのと同じ扱いである。

**深さが体の厚み (体長の 2 割) より離れていれば、重なって見えてよい。** 実際に池の鯉はそうやって擦れ違う。この作品の 6 匹は深さ 34〜140 mm に散らしてあるので、いちばん浅い鯉といちばん深い鯉だけが上下に擦れ違える。

![鯉が互いを避けて泳ぐ 4.3 秒](https://i.gyazo.com/6fcd9ef21eb831074c3a993bf3d464eb.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。4 フレームおきに 64 枚取り、幅 960・15fps にしたもの (等速)。**近づいた 2 匹が触れる前に向きを変えていく**ところを見てほしい。この 4.3 秒の間、いちばん詰まったところでも体と体は 45 mm 離れている。

### 縦に立った鰭と、水平に開いた鰭

**魚の尾鰭と背鰭は体の正中面に立っている。** 真上から見ると板ではなく**切り口**なので、細い刃にしか見えない。扇が開いて見えるのはイルカやクジラで、**あちらの尾だけが水平**である。

| 鰭 | 面の向き | 真上からの見え方 |
| --- | --- | --- |
| 尾鰭 | 正中面 (縦) | 撓んだ細い刃。先へ向かって細り、薄くなる |
| 背鰭 | 正中面 (縦) | 背の上に乗る細い筋。真ん中がいちばん高い |
| 胸鰭 | 水平に近い | 開いた形。後ろへ寝かせて水を掻く |

**撓んでいるときほど尾鰭は太く見える。** 鰭が反ると面が斜めを向くので、真上から見える切り口が広がる — 打ち返す瞬間がいちばん細く、掻いている最中がいちばん太い。振幅 `1 + 1.6 × |撓み|` で効かせてある。

**鰭条は引いていない。** 縦に立った膜の筋は真上からは全部同じ線へ潰れて見えず、胸鰭のほうは 40 画素ほどしかないので、筋を引くと膜ではなく櫛に見えた。

## 直したこと

### 鯉が互いの体を突き抜けていた

避ける相手を**頭の位置だけ**で見ていた。頭が 270 mm 離れていれば力が掛からないので、体長 344 mm の横腹はそのまま重なる。しかも反応が始まるのは触れる直前で、旋回半径が体長の 1.3 倍ある体では間に合わない。**6 匹のうちどれかが重なっている時間が 3 割前後**あった。

| | 直す前 (2 回) | 直した後 (3 回) |
| --- | --- | --- |
| どれかが重なっている時間 | 29% / 38% | 12% / 17% / 18% |
| 間合いの中央値 | 18 / 46 mm | 68 / 70 / 74 mm |
| いちばん長い重なり | 4.3 / 3.8 秒 | 2.9 / 2.9 / 2.8 秒 |

> 風 0.55・餌なしで 35〜65 秒ぶんを毎フレーム測ったものを、走らせるたびに 1 行。物差しは `clearance` (背骨同士のいちばん近いところから互いの半幅を引いたもの。負なら重なっている) として出してあるので、`mokume mcp` の観測から読める。
>
> **いちばん深く食い込んだ 1 回は 84 mm から 75 mm にしかならなかった。** いちばん浅い鯉といちばん深い鯉が真上で擦れ違う組だけは、深さが体の厚みより離れているぶん避ける力を落としてあるためで、これは上を通り抜けているものとして残してある。

**外したものが 3 つある。書いてみて悪くなったので戻した。**

- **体の前半分でも間合いを測る** — 鼻先だけでなく体の前 3 分の 1 からも相手の背骨までを測った。12.4% が 12.7% になっただけで、測る点が 3 倍になるぶん重いので戻した
- **小さいほうが譲る** — 2 匹が同じだけ避けると避けた先でまた鉢合わせるので、小さい側に強く避けさせ、大きい側はそのまま進ませた。**58% まで悪化した。** 譲る側は減速もするのだが、**曲がれる速さは泳ぐ速さに比例する**ので、避ける役を 1 匹に集めると、その 1 匹から真っ先に舵を奪ってしまう
- **減速をやめる** — 上の理屈なら減速は害では、と思って外したら **26.9% へ倍増した。** 首の上限を差し迫ったときだけ緩めてあるので舵は残り、減速したぶんは素直に「相手が前を通り過ぎるのを待つ」として効いていた

### 6 匹とも巻き貝になった

はじめの首振りの上限は速さだけで決めていた (`1.7 + 速さ × 0.006` rad/s)。速さ 70 mm/s ではこれが 2.1 rad/s になり、**旋回半径 33 mm** — 体長 300 mm の鯉が自分の 9 分の 1 の円を回ることになる。鎖が折り返して、6 匹とも丸まった。

いまは**曲がれる速さを体の長さに縛ってある** (`速さ ÷ (体長 × 0.85)`)。魚の最小旋回半径は体長の 1 倍ほどで、そこに合わせた。

### 餌の周りを回り続けて、1 粒も食べなかった

旋回半径を体長に縛った副作用で、**全速のまま寄ると口が届く前に行き過ぎる**ようになった。6.7 秒回して 1 粒も減らなかった (`pellets` を観測して気付いた)。

近づいたら速さを落とす (`min(210, 52 + 距離 × 0.62)`) ようにして直した。半径は速さに比例するので、遅くなれば小さく曲がれる。

### 尾が出す輪だけで、輪の置き場が埋まった

輪は 32 本まで。鯉 6 匹が尾を打つたびに輪を置くので、**それだけで 32 本を使い切り、餌を落としても輪が置けなかった。** 弱りきった輪を落とす閾値を `3.4 × 寿命` から `2.6 ×` へ下げ、尾の輪の寿命も 1.3 秒から 0.85 秒へ縮めた (いまは常時 5〜20 本)。

### 尾の輪が、深さを見ずに水面を叩いていた

輪を置くときに鯉の深さを一度も見ていなかったので、**240 mm 沈んだ鯉も水面直下の鯉と同じ輪を立てていた。** 振幅は巡航で 1.36〜1.71 mm — **撫でた指の輪 (1.3) より強いものが常に 18 本**浮いていることになる。風が凪いでいる間は面で動くものがこれしか無いので、池が沸いて見える。

深さで薄め (上記)、立たない輪は置かないようにした。輪の振幅の最大は 1.65 mm から 1.06 mm へ下がり、餌 (4.0) → 食べた瞬間 (1.8) → 撫でた指 (1.3) → 尾、という序列に収まった。**本数は 17〜18 本で変わらない** — 平均の深さが 85〜105 mm なので、棄却まで届くのは深く沈んだ鯉だけである。

あわせて**起動 1 枚目の一斉打ち**も消した。`beats = 0` / `lastBeat = −1` で始めていたので、`floor(0) ≠ −1` が最初のフレームで 6 匹ぶん同時に成立していた。打ちの数も尾の位相 (`phase`) から数え始めれば、最初の打ちは個体ごとに散る。

### 体が動かないまま、斜めに傾いて滑っていた

泳ぎの波の振幅を**体長の 0.9%** (尾で) しか振っていなかった。しかも巡航の速さを画素で置いていた (70 mm/s) ので、体長 300 mm の鯉は 0.23 体長 / 秒でしか進まず、**尾を 2.6 秒に 1 回しか打たなかった。** 動いて見えるはずがない。

さらに首を振れる速さの上限を体長の 0.85 倍の旋回半径に合わせていたため、**旋回中の体が常に弓なり**で、その曲がりのほうが泳ぎの波より大きかった — 「曲がったまま滑っている」ように見えたのはこれである。

いまは寸法を全部体長に対して置き直し (上表)、振幅を 5〜6% へ、旋回半径を体長の 1.3 倍へ広げてある。振れの伸び方も 2 乗から 1.6 乗へ緩めた — 2 乗では振れるのが後ろ 3 分の 1 だけになり、胴が板のまま尾だけが動いて見える。

### 鯉が近づいただけで餌が消えていた

食べた判定を**体の中心から半径 90 画素**で見ていた。鯉が寄ってくると口が届く前に餌が消えるので、いちばん見たい瞬間が絵に出なかった。

いまは**鼻先から体長の 5.5%** (340 mm の鯉で 19 mm) で、しかも餌が鼻先より前にあることを求める。**口の当たり判定を実寸まで絞ると、そのままでは餌の周りを回り続ける**ので、餌が体長の 0.9 倍以内にあるときだけ旋回半径の縛りを外してある — 魚は遅いところでは体ではなく鰭で向きを変えるので、これは物理のほうに寄せた変更である。

![餌が口元へ入って消える 3.6 秒 (2 倍に拡大)](https://i.gyazo.com/3c18ccce985ec471358662f209e6408a.webp)

> 撮影範囲: 走っているスケッチの面のうち、餌の周り 360×230 画素を 2 倍に拡大したもの (`mokume mcp` の観測が書き出した絵)。6 フレームおきに 36 枚取り、10fps (等速)。**浅黄が鼻先を餌へ着けた瞬間に消える**ところを見てほしい。

### 睡蓮が忙しなく揺れていた

振り子の `g` を 6 分の 1 にしていたので周期が 2.1〜3.2 秒になり、葉が波打つように揺れていた。浮力が重力をほとんど打ち消すことを見込んで 14 分の 1 へ落とし (周期 3.2〜4.9 秒)、振れ幅も 44% へ絞った。

### 鯉ではなくイルカの尾に見えた

尾鰭を**水平に開いた扇**で描いていた。魚の尾鰭は体の正中面に立っているので、真上から見えるのは板ではなく切り口である。扇が開いて見えるのはイルカやクジラのほうで、**あの形にすると、横に振っていても鯉に見えない。**

いまは撓んだ細い刃で描いている。ついでに 2 つ出た:

- **胸鰭が 1 匹も見えていなかった。** 開く向きを付け根の法線と同じ符号で回していたので、鰭が体の下へ潜っていた。符号を逆にして、付け根も体のいちばん太いところ (index 6) から鰓蓋のすぐ後ろ (index 4) へ移した
- **背鰭が体の下に隠れていた。** 鰭をまとめて体の前に描いていたため。背鰭だけは体の後へ回した

### 睡蓮が完全に止まって見えた

はじめは**浮いているものを水面の後に重ねるだけ**にしていた。「真上から見る限り、浮いているものは波でほとんど動かない (上下に揺れるぶんは見えない)」という理屈は間違っていないのだが、**絵としては貼り紙にしか見えなかった。**

見落としていたのは 2 つある。**水粒子の横の動き**は傾きから `−∇h/k` で出せること (上記)、そして**濡れた葉の照りは傾きで大きく動く**ことである。どちらも水面の断片が既に持っている量だけで作れたので、浮いているものを 3 枚目の面へ移してそこで重ねるようにした。**葉が茎に吊られた振り子であること**も足した。

### 風がどこでも同じ強さで、面がワンパターンだった

風を `wind` という**スカラー 1 本**にして、6 枚の揺らぎに同じ倍率で掛けていた。強さはスクロールで動かせたが、**池のどこでも同じ強さ・同じ向きの波が止まることなく立ち続ける**ので、どこを見ても同じ織り目の布に見えた。風が吹いていることは分かるのに、**風が吹いた瞬間が無い。**

直したのは 3 つ。**風を場にした** (斑の重ね合わせで、位置と時刻の関数)。**向きの揃いを崩した** (尺度ごとのずれと、ゆっくりした首振り)。**操作から外した** (スクロールは何もしない)。つまみで動かせるあいだは「いまが強い風なのか弱い風なのか」を人が決めることになり、待っていると来る、という時間が絵から落ちる。

### 泳ぎが一定で、長く映すと同じ絵に見えた

巡航 0.45 体長 / 秒に緩い揺れを足し続けているだけだった。速さが変わるのは餌・手・仲間との
詰まりに反応したときだけで、**自分から何かをすることがない。**

直したのは 4 つ。**1 匹ごとの出来事** (突進・翻る・漂う・渡る) を予定表で置き、**群れの
活気**で数分ごとに全体の勢いを変え、**突進を隣へ伝染**させ、**餌に食いつく瞬間だけ跳ねる**
ようにした。あわせて**深さも漂わせた** (上記)。

**賽は毎フレーム振らない。** 確率で毎フレーム引くと、引く回数がフレームの刻みで変わって
**速い機械ほど忙しい池**になる。風の斑と同じで「何番目の出来事か」から種を作れば、
予定表は時刻の関数のままでいられる。

### 顔が尖って、金魚のような鼻をしていた

**輪郭の幅を背骨の節と同じ 23 等分で置いていた。** 節の間隔は体長の 4.5% で、鯉の鼻先は
その 10 分の 1 の距離で最大半幅の 2 割まで立ち上がる — つまり**丸い鼻先を 1 本の斜辺で
結んでいた**ことになり、上見の輪郭が楔に尖った。値そのものも鼻先で 0.10 と、実測の 0.21 の
半分だった。

直したのは 3 つ。**輪郭を背骨の節から切り離した** (頭のほうだけ細かく刻む 27 点の表にし、
節と節のあいだは補間して読む)。**頭の幅を実測に置き換えた** (上記)。そして**顔の造作を
足した** — 口・鰓蓋の線・**髭 2 対**である。髭は鯉と金魚を分けているものなので、
1 画素の細さでも効く。

あわせて、頭の陰影を平らにした。体の丸み (円柱として法線を振る) を全長へ一様に掛けて
いたが、**鯉の頭は上から見ると平たい** — 顔だけが樽のように光っていた。

### 水面が一度もきらめかなかった

風波の傾きを 0.03 rad で置いていた。**面が 3 度しか傾かないと、反射の向きは真上から 7 度しか離れない** — 太陽が真上から 23 度にあるので、どの画素も一度も太陽に当たらない。実際の風波の傾きは 10〜30 度ある。

## 速さ (2026-09-12 の実測)

| | フレーム率 | 1 フレーム (平均) | 最悪 |
| --- | --- | --- | --- |
| `-c release` | 60.0fps | 16.67ms | 16.7ms |
| 既定 (debug) | 43.7fps | 22.90ms | 33.6ms |

release は垂直同期に張り付いているので**本当の余力は分からない** (16.67ms は上限で、そこまでしか測れない)。輪が 32 本のときも 60fps を保っている。

**毎フレームの仕事はほとんど GPU 側にある。** CPU がやるのは鯉 6 匹の背骨 (23 節) と輪の一覧を詰めることだけで、水面の断片が画素ごとに 6 枚の揺らぎと最大 32 本の輪を 3 か所で引く (焦線を見るのに 2 点ずらす)。風の場はそこに 1 枚の長い揺らぎと斑 2 つぶんの包絡を足すだけなので、debug で測った 1 フレームは 22.9ms から動かなかった。輪は**平方根を取る前に包絡の外を捨てる**ので、どの画素でも実際に効くのは 1〜3 本である。

## 踏んだもの

### 2D の頂点に、貼る絵を束ねずに体の座標を持たせられない

`vertex(x, y, u, v)` で書いた読み取り位置は、**貼る絵を束ねていないと捨てられる** (`Canvas.textureUV` が `currentPicture` を見て `nil` を返す)。断片の `in.uv` は 0 のままになるので、体の座標で模様を塗れない。

Grain が立体で踏んだ [mokume#367](https://github.com/mokume-metal/mokume/issues/367) (断片が表面の位置を知らない) と同じ形の穴が、**2D の側に残っている**。あちらは `Fragment.shapePosition` で埋まったが、平面では 0 である。

いま通している抜け道は **1×1 の白い絵を束ねること**。読み取り位置は絵の画素数で割られる決まりなので、1×1 なら書いた 0…1 がそのまま届く。断片は `in.texel` を一度も読まない。

戻した先: [mokume#1140](https://github.com/mokume-metal/mokume/issues/1140)。

### 走らせ直すと、前に送った入力がもう一度配送される

`.mokume/input/request.json` が残っていると、**起動するたびに応答済みの要求がもう一度配送される。** `mokume watch` は保存のたびにプロセスを差し替えるので、保存するたびに過去の入力が再生されることになる。

この作品では、窓口から送った餌やり (`mouseDown` × 3) が起動のたびに再生され、**振幅 4.0 mm の輪が 3 本立って、鯉がそこへ突進していた。** 輪の寿命が 8.8 秒なので「起動して 10 秒くらいは水面が荒れ、そのあと落ち着く」という症状に見え、スケッチ側を疑って切り分けに時間がかかった — フレーム時間を 75 秒ぶん測って**起動直後から一定**だと確かめてから、ようやく入力のほうへ辿り着いた。

`report.json` には応答済みの `id` が書かれているのに、新しいプロセスがそれを読まない。ADR-0018 決定 3 の「同じ識別子は二度処理しない」が、`RequestFile` ではプロセス内のメモリにしか無いためである。

戻した先: [mokume#1143](https://github.com/mokume-metal/mokume/issues/1143)。

### 揺らぎの傾きを返す口が無い

`mokume_noise` は値しか返さない。傾きが要る用途 (この作品では水面の法線) では隣を引くしかなく、**その差分が階段になって鏡面反射がギラつく。** 混ぜ方 (3t² − 2t³) の微分は閉じた形で書けるので、口としては値と傾きを一緒に返せる。

いまは同じ式を自分で書いている (`pond_swell`)。**mokume 側の `ValueNoise` とは別実装なので、同じ種でも同じ値は出ない** — この作品はどちらの値にも依存していないので困っていないが、口があれば持たなくて済む。

戻した先: [mokume#1141](https://github.com/mokume-metal/mokume/issues/1141)。
