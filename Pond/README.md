# Pond — 池の水面と錦鯉

![風 0.55 の池。錦鯉 6 匹が泳ぎ、水面の傾きが底を歪め、太陽のきらめきが散る](https://i.gyazo.com/76684e809082fa9c7b20aee2a1275b83.png)

制作トラック ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md)) の 9 本目。

**水っぽく描くのではなく、水面の傾きから絵を導いている。** 高さ場 `h(p, t)` を持ち、その勾配 `∇h` だけを絵に使う — 屈折も焦線も鏡面反射も、全部そこから出る。だから**風を 0 にすれば傾きが消え、底の砂利が歪みなく見える**し、上げれば底が崩れて代わりに面がきらめく。

既存 8 本が通していない経路が 3 つあった。**面を 2 枚焼いて断片から名前で読む**こと、**CPU が書いた数を断片が読む**こと (`Numbers` の CPU 書き込み)、そして **2D の頂点に形自身の座標を持たせて模様を貼る**ことである。3 つ目は素直には通らず、抜け道で通して [mokume#1140](https://github.com/mokume-metal/mokume/issues/1140) へ戻した。

![餌を落としてから鯉が寄って食べるまでの 5.2 秒](https://i.gyazo.com/5b1492d27b2b89056d9ce408ff9ea953.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵で、画面は撮っていない)。餌を 1 粒落とした直後から 5.2 秒ぶんを 4 フレームおきに 78 枚取り、幅 720・15fps にしたもの (等速)。**1 枚では読めないものを見てほしい** — 落ちた輪が広がりながら底を歪ませ、離れていた鯉が向きを変えて寄り、口が届いたところで餌が消える。輪の**峰が後ろから湧いて前で消えて**いくのは、包絡が群速度で・峰が位相速度で動いているためである (下記)。

## 走らせる

```bash
mokume run Pond -c release    # 作って走らせる
mokume watch Pond -c release  # 保存したら作り直して差し替える
mokume mcp Pond               # 走っているスケッチを外から観測する
```

**`-c release` を付ける。** `run` / `watch` の既定は debug で、そこでは 43.7fps まで落ちる (下記「速さ」)。

## 触る

| 操作 | 効くもの |
| --- | --- |
| クリック | **餌を落とす。** いちばん強い輪が広がり、鯉が寄って食べる。消えるのは**口へ届いたときだけ**で、食べた場所にも小さな輪が出る |
| マウスを動かす | **水面を撫でる。** 指の跡に沿って輪が出て、**鯉は逃げる** (1.6 秒かけて怖さが引く) |
| スクロール | **風の強さ (0〜1.6)。** 0 で波が止まり底が澄む。上げると底が崩れ、面がきらめく |
| スペース | 餌を片付ける |
| R | はじめへ戻す (餌と輪を消し、風を 0.55 へ) |

### 風を 0 にすると、底が歪まなくなる

| 風 0 | 風 1.60 |
| --- | --- |
| [![](https://i.gyazo.com/d68ab5f8b6ee8f0b3f758ed384d5a18c.png)](https://i.gyazo.com/d68ab5f8b6ee8f0b3f758ed384d5a18c.png) | [![](https://i.gyazo.com/d5bb3fb91409cfcaed205f6380753073.png)](https://i.gyazo.com/d5bb3fb91409cfcaed205f6380753073.png) |
| 砂利の輪郭が出る。焦線も消え、太陽は**1 枚の玉**として映る | 底が読めなくなり、代わりに面じゅうに**きらめきが散る** |

**面が傾かなければ、屈折も焦線もきらめきも出ない。** 3 つとも同じ `∇h` から出ているので、スクロール 1 本で同時に消える。**太陽の玉が凪のときだけ丸いのも同じ理由**で、面が平らなら反射の向きが揃い、傾きがあれば向きが散って玉が粒に割れる (これが「きらめき」の正体である)。

## どの mokume で描いたか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある。** この作品のコミットを checkout すれば mokume も当時の版に戻る。

**works で最初の `v0.7.1` である** — ほかの 8 本はまだ `v0.7.0` を引いている ([#49](https://github.com/mokume-metal/works/issues/49) が追随を追っている)。`Package.swift` は `from: "0.7.0"` と書いてあり、作った日にそこから解決されたのが `0.7.1` だった。

**同じフレーム番号からは同じ絵が出る** (mokume の [ADR-0001](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0001-founding-principles.md) 原則 2)。この作品は乱数を使わない — 砂利と水草と睡蓮の配置は、種を持った自前の並び (`Scatter`) が起動時に 1 度だけ決める。**触っていない限り、同じ番号のフレームは同じ絵になる。**

**絵のハッシュは持っていない**ので、版を上げて何かが動いたことに気付くのは窓を開けて目で見たときである。

## 何がどう動いているか

### 尺度を決めてある — 1 画素 = 1 mm

画面 1920 画素は **1.92 m の池**で、波長も水深も鯉の体長もその尺度の実寸である。尺度を決めたので、**波の速さを手で置かずに済む**:

```
c(λ) = √( g/k + (σ/ρ)·k )      k = 2π/λ
```

水の定数 (g = 9810 mm/s²、σ/ρ = 72800 mm³/s²) をそのまま入れると、位相速度は **λ = 17.1 mm で最小の 231 mm/s** を取る。雨粒の輪がどれも同じくらいの速さで広がって見えるのはこの谷のせいで、置いた数ではなく式から出てくる。

| λ (mm) | 22 | 38 | 66 | 112 | 190 | 330 |
| --- | --- | --- | --- | --- | --- | --- |
| 位相速度 `c` (mm/s) | 235 | 267 | 332 | 423 | 547 | 719 |
| 群速度 `c_g` (mm/s) | 206 | 179 | 187 | 221 | 278 | 361 |

### 絵にするのは高さではなく傾きである

真上から静かな水を見ても高さは見えない。見えるのは「傾いた面がどこを映し、どこを透かしているか」だけなので、水面が外へ渡すのは `h` ではなく `∇h` になる。

- **屈折** — 法線 `n = (−∂h/∂x, −∂h/∂y, 1)` と視線から Snell (`refract`) で水中の向きを出し、深さぶんだけ読み位置をずらす。**平らな水面での見え方を基準に、波のぶんだけ**取る (隅では視線が斜めなので、引かないと波が無くても絵が歪む)
- **焦線 (caustics)** — 上の写像のヤコビ行列式そのもの。底へ落ちる像の面積比が `det J` で、明るさはその逆数である。**屈折を止めれば焦線も消える**のが式として繋がっている
- **鏡面反射** — Schlick のフレネル (F0 = 0.02)。**真上から見た水の反射率は 2% しかない**ので、見えるのは太陽だけ。それで十分に光る — 太陽の輝度が桁違いだからで、水面がきらめく理由がそれである

**勾配は解析微分で出している。** 有限差分にすると隣り合う画素で傾きが階段になり、鏡面反射がその折れを拾って面じゅうがギラつく (太陽の玉が点ではなく格子に映る)。

### 平面波の重ね合わせをやめた

はじめは**向きと波長の違う進行波を 14 本重ねて**いた。式としては正しいのだが、**焦線が斜めの格子として整然と並び、池の底が織物に見えた** (同じ大きさの明るい斑が、一定の間隔で斜めに並ぶ)。有限個の平面波の和は準周期なので、位相をずらしても向きを ±80 度まで散らしても、格子がずれるだけで消えない。実際の水面は**波数が連続で、位相が場所ごとに無関係**である。

いまは**尺度ごとの格子の揺らぎ**を 6 枚重ねている (22〜330 mm)。繰り返しが無く、しかも**尺度ごとに自分の波長が要求する速さで流れる** — 上の表のとおり、22 mm の細波は 235 mm/s、330 mm のうねりは 719 mm/s で走る。峰が風に直交して伸びるよう、風向きの座標へ回してから横方向だけ 0.62 倍に潰してある。

揺らぎは**値と傾きを一度に返す自前のもの** (`pond_swell`) である。mokume の `mokume_noise` は値しか返さないので、傾きを取るには隣を引くことになり、上に書いた階段が出る。

### 峰は包絡の後ろから湧いて、前で消える

[![餌を落とした輪と、寄ってくる鯉](https://i.gyazo.com/03d808c8710c530ec19d7bdc4e784e0a.png)](https://i.gyazo.com/03d808c8710c530ec19d7bdc4e784e0a.png)

輪の広がる速さは**群速度**、峰の走る速さは**位相速度**で、この波長域では後者が前者の 1.7 倍ある (λ = 58 mm で 314 / 182)。だから波束の中で峰が前へ追い越していき、先頭で消える。**足した細工ではなく、`c` と `c_g` を別々に使った帰結**である。

輪を置くのは 4 つ: 落ちた餌 (振幅 4.0 mm・λ 58)、食べた瞬間 (1.8 mm・λ 36)、撫でた指 (1.3 mm・λ 46)、そして**鯉が尾を打つたび** (0.75 + 速さ × 0.0045 mm・λ 78)。航跡は描いていない — 打つたびに置いた輪が後ろへ残るので、結果として V 字に見える。

### 3 枚の面を 1 枚にする

| 面 | 中身 | 深さ |
| --- | --- | --- |
| `Bed` (960×540) | 砂・砂利 240 個・水草・**鯉と睡蓮の影** | 420 mm |
| `School` (1920×1080) | 鯉の体と鰭だけ。背景は透明 | 84 mm |
| `Surface` (1920×1080) | 睡蓮・花びら・餌。背景は透明 | 水の上 |
| 主面 | 上の 3 枚を名前で読み、水面の断片が 1 枚に合成する | — |

**深さごとに屈折のずれが違う**ので分けてある。底と鯉が別々に揺れることが、この絵の奥行きになっている。底が半分の解像度なのは**水越しの底は暈けてよい**からで、線形補間の甘さがそのまま暈けになる。

濁りは Beer-Lambert で、**行きと帰りの 2 倍の道のり**を通る。赤から先に失われるので深いほど緑へ寄る (底で赤 28% / 緑 63% / 青 42% が残る)。**匹ごとの深さの差**は水面の断片ではなく、鯉を描くときに焼き込んである。

### 浮いているものも、水面の断片が受け持つ

睡蓮・花びら・餌は**もう 1 枚の面へ描き**、水面の断片が最後に重ねる。水越しに見ていないので屈折も濁りも掛からないが、代わりに 2 つが効く。

**横へ流されるぶん。** 深水波の水粒子は円を描く。高さが `a·cos(kx − ωt)` なら横の変位は `a·sin(kx − ωt)` で、**傾き `∂h/∂x = −a·k·sin` を `−1/k` 倍するとちょうどそれになる。** だから傾きさえ持っていれば横の動きは別に数えなくてよい (Gerstner 波が使うのと同じ関係)。**自分より短い波は外す** — 睡蓮の葉は 200 mm ほどあるので、22 mm の細波はその下をすり抜けていく (`Water.floatFollows` が下限)。輪も乗せてあるので、**落とした餌は自分が立てた輪に揺られる。**

**濡れた葉の照り。** 面の傾きから鏡面反射を出すので、**照りが葉の上を細い帯として流れる。** 山を広く取ると葉が一枚まるごと灰色に飛ぶので、鋭い山 (指数 260) を小さく乗せてある。

**葉そのものは茎に吊られた振り子である。** 風に押されて風下へ寄り、戻ってくる。角振動数は振り子の式 `√(g/L)` そのままで、長い茎ほどゆっくり大きく振れる (水中では浮力が重力をほとんど打ち消すので `g` は 14 分の 1。周期は 3.2〜4.9 秒)。**波の 1 つ 1 つが与える捻りは数えていない** — 高さ場は断片の中にしかなく、CPU 側へ写せば式が 2 か所に住む。

![睡蓮が茎に吊られて振れる 5 秒](https://i.gyazo.com/859c454c064b05b88f039913cebaf28a.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。5 フレームおきに 60 枚取り、幅 960・12fps にしたもの (等速)。右下の葉は**左端が 2.8 秒かけて 80 画素往復する** (実測)。葉の上を照りが流れるところと、花びらが波に乗って動くところもあわせて見てほしい。

### 鯉

背骨は**引かれる鎖**で作る。頭だけが自分で進み、後ろの節は前の節から一定の距離で引かれるので、曲がれば体が後から湾曲する — 旋回の形を手で書かなくてよい。そこへ頭から尾へ進む波を重ねる。**泳ぎの波は推進の原因ではなく、進んだ結果へ後から足している** (ここは物理ではなく約束である)。

**寸法は全部体長に対して置いてある。**

| | |
| --- | --- |
| 巡航の速さ | 体長の 0.45 倍 / 秒 |
| 尾を 1 打ちで進む距離 | 体長の 0.45 倍 (鯉は効率のよい泳ぎ手ではない) |
| 尾の振れ幅 (片振幅) | 体長の 5〜6% |
| 振れの伸び方 | 頭からの距離の 1.6 乗 |
| 最小旋回半径 | 体長の 1.3 倍 |

![錦鯉が体をくねらせて泳ぐ 3.2 秒](https://i.gyazo.com/360bc1918004b495b17f0fabd6f7b731.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。4 フレームおきに 48 枚取り、幅 960・15fps にしたもの (等速)。**体が頭から尾へ順に波打っている**ところと、**尾鰭が撓みながら遅れて振れる**ところを見てほしい。

体は断片で塗る。輪郭の頂点に**体の座標** (u = 鼻から尾、v = 左から右) を持たせてあるので、泳いで曲がれば斑も一緒に歪み、画面に貼り付かない。品種は 6 つで、**同じ品種でも個体ごとに斑が違う** (種が違う):

| | 地 | 斑 |
| --- | --- | --- |
| 紅白 | 白 | 紅 |
| 大正三色 | 白 | 紅 + 背に墨 |
| 昭和三色 | 黒 | 紅 + 白 |
| 黄金 | 金 | 単色。鱗の照りだけが模様 |
| 浅黄 | 藍 (背) | 脇腹が緋、背に網目 |
| 白写り | 黒 | 白 |

斑の縁は `smoothstep` の幅 0.04 で切ってある。**にじませると鯉に見えない** — 錦鯉の評価軸が「キワ」であるのはそのためである。

### 縦に立った鰭と、水平に開いた鰭

**魚の尾鰭と背鰭は体の正中面に立っている。** 真上から見ると板ではなく**切り口**なので、細い刃にしか見えない。扇が開いて見えるのはイルカやクジラで、**あちらの尾だけが水平**である。

| 鰭 | 面の向き | 真上からの見え方 |
| --- | --- | --- |
| 尾鰭 | 正中面 (縦) | 撓んだ細い刃。先へ向かって細り、薄くなる |
| 背鰭 | 正中面 (縦) | 背の上に乗る細い筋。真ん中がいちばん高い |
| 胸鰭 | 水平に近い | 開いた形。後ろへ寝かせて水を掻く |

**撓んでいるときほど尾鰭は太く見える。** 鰭が反ると面が斜めを向くので、真上から見える切り口が広がる — 打ち返す瞬間がいちばん細く、掻いている最中がいちばん太い。振幅 `1 + 1.6 × |撓み|` で効かせてある。

![尾鰭が撓みながら振れる 4 秒](https://i.gyazo.com/3b8f5974c978fabea217b6de15d9ee92.webp)

> 撮影範囲: 走っているスケッチの面だけ (`mokume mcp` の観測が書き出した絵)。4 フレームおきに 60 枚取り、幅 960・15fps にしたもの (等速)。**尾鰭が振れるたびに太さが変わる**ところと、**胸鰭が後ろへ寝たまま漕いでいる**ところを見てほしい。

**鰭条は引いていない。** 縦に立った膜の筋は真上からは全部同じ線へ潰れて見えず、胸鰭のほうは 40 画素ほどしかないので、筋を引くと膜ではなく櫛に見えた。

## 直したこと

### 6 匹とも巻き貝になった

はじめの首振りの上限は速さだけで決めていた (`1.7 + 速さ × 0.006` rad/s)。速さ 70 mm/s ではこれが 2.1 rad/s になり、**旋回半径 33 mm** — 体長 300 mm の鯉が自分の 9 分の 1 の円を回ることになる。鎖が折り返して、6 匹とも丸まった。

いまは**曲がれる速さを体の長さに縛ってある** (`速さ ÷ (体長 × 0.85)`)。魚の最小旋回半径は体長の 1 倍ほどで、そこに合わせた。

### 餌の周りを回り続けて、1 粒も食べなかった

旋回半径を体長に縛った副作用で、**全速のまま寄ると口が届く前に行き過ぎる**ようになった。6.7 秒回して 1 粒も減らなかった (`pellets` を観測して気付いた)。

近づいたら速さを落とす (`min(210, 52 + 距離 × 0.62)`) ようにして直した。半径は速さに比例するので、遅くなれば小さく曲がれる。

### 尾が出す輪だけで、輪の置き場が埋まった

輪は 32 本まで。鯉 6 匹が尾を打つたびに輪を置くので、**それだけで 32 本を使い切り、餌を落としても輪が置けなかった。** 弱りきった輪を落とす閾値を `3.4 × 寿命` から `2.6 ×` へ下げ、尾の輪の寿命も 1.3 秒から 0.85 秒へ縮めた (いまは常時 5〜20 本)。

### 体が動かないまま、斜めに傾いて滑っていた

泳ぎの波の振幅を**体長の 0.9%** (尾で) しか振っていなかった。しかも巡航の速さを画素で置いていた (70 mm/s) ので、体長 300 mm の鯉は 0.23 体長 / 秒でしか進まず、**尾を 2.6 秒に 1 回しか打たなかった。** 動いて見えるはずがない。

さらに首を振れる速さの上限を体長の 0.85 倍の旋回半径に合わせていたため、**旋回中の体が常に弓なり**で、その曲がりのほうが泳ぎの波より大きかった — 「曲がったまま滑っている」ように見えたのはこれである。

いまは寸法を全部体長に対して置き直し (上表)、振幅を 5〜6% へ、旋回半径を体長の 1.3 倍へ広げてある。振れの伸び方も 2 乗から 1.6 乗へ緩めた — 2 乗では振れるのが後ろ 3 分の 1 だけになり、胴が板のまま尾だけが動いて見える。

### 鯉が近づいただけで餌が消えていた

食べた判定を**体の中心から半径 90 画素**で見ていた。鯉が寄ってくると口が届く前に餌が消えるので、いちばん見たい瞬間が絵に出なかった。

いまは**鼻先から体長の 5.5%** (340 mm の鯉で 19 mm) で、しかも餌が鼻先より前にあることを求める。**口の当たり判定を実寸まで絞ると、そのままでは餌の周りを回り続ける**ので、餌が体長の 0.9 倍以内にあるときだけ旋回半径の縛りを外してある — 魚は遅いところでは体ではなく鰭で向きを変えるので、これは物理のほうに寄せた変更である。

![餌が口元へ入って消える 3.6 秒 (2 倍に拡大)](https://i.gyazo.com/3c18ccce985ec471358662f209e6408a.webp)

> 撮影範囲: 走っているスケッチの面のうち、餌の周り 360×230 画素を 2 倍に拡大したもの (`mokume mcp` の観測が書き出した絵)。6 フレームおきに 36 枚取り、10fps (等速)。**浅黄が鼻先を餌へ着けた瞬間に消える**ところを見てほしい。

### 睡蓮が忙しなく揺れていた

振り子の `g` を 6 分の 1 にしていたので周期が 2.1〜3.2 秒になり、葉が波打つように揺れていた。浮力が重力をほとんど打ち消すことを見込んで 14 分の 1 へ落とし (周期 3.2〜4.9 秒)、振れ幅も 44% へ絞った。

### 鯉ではなくイルカの尾に見えた

尾鰭を**水平に開いた扇**で描いていた。魚の尾鰭は体の正中面に立っているので、真上から見えるのは板ではなく切り口である。扇が開いて見えるのはイルカやクジラのほうで、**あの形にすると、横に振っていても鯉に見えない。**

いまは撓んだ細い刃で描いている。ついでに 2 つ出た:

- **胸鰭が 1 匹も見えていなかった。** 開く向きを付け根の法線と同じ符号で回していたので、鰭が体の下へ潜っていた。符号を逆にして、付け根も体のいちばん太いところ (index 6) から鰓蓋のすぐ後ろ (index 4) へ移した
- **背鰭が体の下に隠れていた。** 鰭をまとめて体の前に描いていたため。背鰭だけは体の後へ回した

### 睡蓮が完全に止まって見えた

はじめは**浮いているものを水面の後に重ねるだけ**にしていた。「真上から見る限り、浮いているものは波でほとんど動かない (上下に揺れるぶんは見えない)」という理屈は間違っていないのだが、**絵としては貼り紙にしか見えなかった。**

見落としていたのは 2 つある。**水粒子の横の動き**は傾きから `−∇h/k` で出せること (上記)、そして**濡れた葉の照りは傾きで大きく動く**ことである。どちらも水面の断片が既に持っている量だけで作れたので、浮いているものを 3 枚目の面へ移してそこで重ねるようにした。**葉が茎に吊られた振り子であること**も足した。

### 水面が一度もきらめかなかった

風波の傾きを 0.03 rad で置いていた。**面が 3 度しか傾かないと、反射の向きは真上から 7 度しか離れない** — 太陽が真上から 23 度にあるので、どの画素も一度も太陽に当たらない。実際の風波の傾きは 10〜30 度ある。

## 速さ (2026-09-12 の実測)

| | フレーム率 | 1 フレーム (平均) | 最悪 |
| --- | --- | --- | --- |
| `-c release` | 60.0fps | 16.67ms | 16.7ms |
| 既定 (debug) | 43.7fps | 22.90ms | 33.6ms |

release は垂直同期に張り付いているので**本当の余力は分からない** (16.67ms は上限で、そこまでしか測れない)。輪が 32 本のときも 60fps を保っている。

**毎フレームの仕事はほとんど GPU 側にある。** CPU がやるのは鯉 6 匹の背骨 (23 節) と輪の一覧を詰めることだけで、水面の断片が画素ごとに 6 枚の揺らぎと最大 32 本の輪を 3 か所で引く (焦線を見るのに 2 点ずらす)。輪は**平方根を取る前に包絡の外を捨てる**ので、どの画素でも実際に効くのは 1〜3 本である。

## 踏んだもの

### 2D の頂点に、貼る絵を束ねずに体の座標を持たせられない

`vertex(x, y, u, v)` で書いた読み取り位置は、**貼る絵を束ねていないと捨てられる** (`Canvas.textureUV` が `currentPicture` を見て `nil` を返す)。断片の `in.uv` は 0 のままになるので、体の座標で模様を塗れない。

Grain が立体で踏んだ [mokume#367](https://github.com/mokume-metal/mokume/issues/367) (断片が表面の位置を知らない) と同じ形の穴が、**2D の側に残っている**。あちらは `Fragment.shapePosition` で埋まったが、平面では 0 である。

いま通している抜け道は **1×1 の白い絵を束ねること**。読み取り位置は絵の画素数で割られる決まりなので、1×1 なら書いた 0…1 がそのまま届く。断片は `in.texel` を一度も読まない。

戻した先: [mokume#1140](https://github.com/mokume-metal/mokume/issues/1140)。

### 揺らぎの傾きを返す口が無い

`mokume_noise` は値しか返さない。傾きが要る用途 (この作品では水面の法線) では隣を引くしかなく、**その差分が階段になって鏡面反射がギラつく。** 混ぜ方 (3t² − 2t³) の微分は閉じた形で書けるので、口としては値と傾きを一緒に返せる。

いまは同じ式を自分で書いている (`pond_swell`)。**mokume 側の `ValueNoise` とは別実装なので、同じ種でも同じ値は出ない** — この作品はどちらの値にも依存していないので困っていないが、口があれば持たなくて済む。

戻した先: [mokume#1141](https://github.com/mokume-metal/mokume/issues/1141)。
